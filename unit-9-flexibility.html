Unit 9 · Structural & Behavioral Flexibility

Decorator & Adapter Patterns

“Decorator changes the skin of an object; Strategy changes its guts.” — Erich Gamma et al. (GoF Design Patterns)

Extending object functionality at runtime without inheritance explosion, and converting incompatible interfaces so legacy systems integrate seamlessly.

1

9.3 The Decorator Pattern

Dynamic runtime wrapping as an alternative to subclass explosion.

GoF Intent: Attach additional responsibilities to an object dynamically. Decorators provide a flexible alternative to subclassing for extending functionality.

The Starbuzz Coffee Dilemma: A coffee shop offers HouseBlend, DarkRoast, Espresso, and Decaf. Customers can customize with Milk, Soy, Mocha, and Whip. Creating static subclasses for every combination leads to HouseBlendWithSoyAndMocha, producing over 100 classes!

The Solution: Start with a base beverage and wrap it with decorators. The client treats the outermost decorator as the Beverage!

Java Real-World Example: java.io Streams

InputStream is = new BufferedInputStream(new GZIPInputStream(new FileInputStream("data.gz")));
Here, FileInputStream is the concrete component; GZIPInputStream and BufferedInputStream are decorators augmenting decompression and buffering capabilities!

9.5 The Adapter Pattern

Translating an existing interface to match client expectations.

GoF Intent: Convert the interface of a class into another interface clients expect. Adapter lets classes work together that couldn't otherwise because of incompatible interfaces.

1. Object Adapter (Composition)

Adapter implements Target and holds an internal reference to Adaptee. Preferred in Java because it adheres to "Favor composition over inheritance."

2. Class Adapter (Multiple Inheritance)

Adapter inherits from both Target and Adaptee. Feasible in C++, but not possible in single-inheritance languages like Java.

Architectural Comparison

Pattern Primary Purpose Interface Relationship
Decorator Adds responsibilities dynamically without changing interface Same interface as wrapped component
Adapter Converts an incompatible interface to match target Different interface (adapts Old to New)
Strategy Alters the internal algorithm/guts via delegation Context delegates to Strategy interface

9.7 Questions for Self-Study

Exam Drill What are the disadvantages of the Decorator pattern?
  1. Proliferation of Small Objects: Using decorators creates many tiny, similar objects (as seen in java.io), which can make debugging and stack traces difficult to follow.
  2. Type Identity Issues: Client code relying on concrete types (instanceof checks) will fail because an object wrapped by a decorator is no longer directly an instance of the concrete component.
  3. Instantiation Complexity: Initializing an object requires wrapping multiple layers (mitigated by using a Factory or Builder).

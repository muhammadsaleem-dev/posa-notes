Official Exam Question 6 · Unit 9 (Decorator)

Which of the OOP principles does decorator primarily follow: Inheritance or composition and briefly explain why?

Official Solution & Rubric Click to reveal Prof. Schäfer's model answer

Primary Principle: Composition (Object Composition over Class Inheritance)

Official Model Explanation:

  • The Decorator pattern primarily follows object composition. The decorator maintains an instance variable referencing the wrapped component (protected Component component;) and delegates client requests to it dynamically at runtime.
  • While Decorator uses inheritance, it does so solely for type conformance (so the decorator can stand in wherever a Component is expected), NOT to inherit behavior. The behavior itself is obtained through composition.
  • This prevents the subclass explosion problem (e.g., Starbuzz coffee with 64 static subclasses) by allowing responsibilities to be layered dynamically like an onion.
⚠️ Professor Gotcha / Deduction Trap: Answering "Inheritance" or simply "both" without clarifying that inheritance is only used for subtyping/interface matching while composition provides the actual functional extension costs up to 50% of points.
Official Exam Question 7 · Unit 11 (MVC)

What is the main task/role of the model in MVC?

Official Solution & Rubric Click to reveal Prof. Schäfer's model answer

Official Model Answer:

  1. Encapsulates Business Data & Domain State: The Model holds the actual application data, business logic, entities, invariants, and persistence rules.
  2. Complete Independence from Presentation: The Model has zero knowledge of how data is rendered on screen (it never imports GUI libraries or references Views/Controllers).
  3. Observer Subject Role: The Model acts as the Subject in the Observer pattern. When its internal state changes (triggered by Controller actions), it broadcasts notifications to registered View observers so they update automatically.
⚠️ Professor Gotcha / Deduction Trap: Stating that the Model directly updates the View (e.g. model.updateView()) is an automatic point deduction. The Model merely notifies observers; the View pulls data from the Model!
Official Exam Question 8 · Unit 1 & Unit 2

How does the Strategy Pattern differ from the Template Method Pattern?

Official Solution & Rubric Click to reveal Prof. Schäfer's model answer

Official Model Answer:

Dimension Strategy Pattern Template Method Pattern
Mechanism Object Composition & Delegation Class Inheritance & Subclassing
Binding Time Dynamic at runtime (hot-swappable algorithms) Static at compile-time (subclass binding)
Control Granularity Swaps the entire algorithm via an interface Defines the skeletal invariant algorithm; subclasses override steps
Design Principle Favor composition over inheritance Hollywood Principle ("Don't call us, we'll call you!")
⚠️ Professor Gotcha: Remember the classic quote from GoF: "Template Method uses inheritance to vary parts of an algorithm. Strategy uses composition to vary the entire algorithm."

Module A: Core Design Patterns (Strategy, Factory, Adapter, Decorator)

From POS-exams-notes.pdf
Exam Task A.1 · Strategy in Standard Libraries

Explain how the C function pointer compar in qsort() or Python's map() function represents the Strategy Pattern.

Official Solution Click to reveal model answer

Model Answer:

  • In C's qsort(base, num, size, compar), the sorting engine is completely decoupled from the comparison logic. The function pointer compar acts as a Concrete Strategy passed into the context at runtime, allowing arbitrary sorting orders without modifying qsort.
  • Similarly, Python's map(function, iterable) dynamically applies an injected strategy function $f(x)$ across a collection without hardcoding transformation logic.
Exam Task A.2 · Abstract Factory Extensibility (GHJV95 MazeFactory)

In [GHJV95], an Abstract Factory is composed of Factory Methods, each with exactly one signature. Does this imply that the Factory Method can only create an object in one way? What do you do if you want to specify room color & size in MakeRoom()?

Official Solution Click to reveal model answer

Model Answer:

No! The fixed signature merely defines the abstract interface; it does NOT restrict the internal instantiation logic of concrete subclasses. To support color and size:

  1. Method Overloading: Provide an overloaded MakeRoom(int n, Color c, Size s) while preserving backwards compatibility for the original method.
  2. Parameter Object: Pass a RoomSpecification object holding optional attributes.
  3. Dynamic Prototyping: Use a Prototype Factory where parameters configure the cloned instance.
Exam Task A.3 · Object vs. Class Adapter

Why is an Object Adapter generally preferred over a Class Adapter, and why is a Class Adapter impossible in Java when adapting two concrete classes?

Official Solution Click to reveal model answer

Model Answer:

An Object Adapter uses composition: it holds an instance of the Adaptee. This adheres to "Favor object composition over class inheritance" and allows a single adapter to work polymorphically with an Adaptee and any of its subclasses.

A Class Adapter requires multiple class inheritance (inheriting publicly from Target and privately from Adaptee). Because Java does not support multiple class inheritance, a Class Adapter is impossible in Java unless Target is a pure Java interface.

Module B: Case Study JUnit (Cook’s Tour) & Christopher Alexander

Exam Task B.1 · JUnit Extension Points

From looking at the JUnit UML diagram, where are the extension points used when using JUnit in a regular way vs extending JUnit with new framework capabilities?

Official Solution Click to reveal model answer

Regular Usage Extension Points:

  1. Subclassing TestCase and adding test methods.
  2. Overriding the hook methods setUp() and tearDown().

Framework-Level Extension Points:

  1. Overriding runBare() to introduce custom test decorators or timing interceptors.
  2. Subclassing TestSuite or implementing Test directly.
  3. Implementing TestListener on TestResult to attach new UI/CLI runners.
Exam Task B.2 · Christopher Alexander's Building Patterns

Name and explain 4 architectural building patterns from Christopher Alexander's 1977 book. Can you implement a reusable binary "pattern library" for software?

Official Solution Click to reveal model answer

Alexander's Physical Patterns:

  • Ring Roads: Strategic placement of loop roads to distribute traffic around urban peripheries.
  • Window Place: Deep low-sill windows with built-in seats creating natural human gathering alcoves.
  • South Facing Outdoors: Orienting outdoor courtyards south to maximize natural daylight.
  • Street Cafes: Public cafes activating street life and human social cohesion.

Can we implement a reusable binary Pattern Library?

NO. Patterns are abstract structural configurations that resolve conflicting forces in a specific context. They are not concrete code components (like a DLL or Jar library) that can be linked; they must be instantiated and adapted anew in each specific domain.

Module C: SOLID Principles & Automated Verification

From POS-exams-notes.pdf
Exam Task C.1 · Automated LSP Conformance Check

Can you check for conformance to the Liskov Substitution Principle (LSP) automatically using static analysis tools? Why or why not?

Official Solution Click to reveal model answer

Official Model Answer:

Not entirely. Static analysis compilers can check syntactic subtyping (method signature names, parameter contravariance, return type covariance, and exception throwing rules).

However, LSP is fundamentally about behavioral subtyping and semantic invariants (e.g. pre-conditions cannot be strengthened, post-conditions cannot be weakened, and history constraints must hold). A `Square` class can syntactically override `setWidth()` without any compiler errors, but it breaks the client's invariant that changing width does not alter height. Verifying behavioral invariants requires formal contract specification (Design by Contract) or human domain judgment.

Exam Task C.2 · Does "This class adheres to OCP" make sense?

Does the sentence: “This class adheres to the Open Closed Principle” make sense in software architecture?

Official Solution Click to reveal model answer

Official Model Answer:

Yes, conceptually and grammatically it makes sense in object-oriented design. Saying a class adheres to OCP means it is structured (via polymorphism, interfaces, and protected hooks) so that its behavior can be extended without modifying its compiled source code.

However, architects note that no class can be 100% closed against all possible changes. OCP is achieved relative to anticipated axes of change.

Module D: Package Architecture & The Main Sequence Metrics

From POS-exams-notes.pdf
Exam Task D.1 · Main Sequence Distance Calculation

Given a package $P$ with 2 abstract classes, 8 concrete classes, 15 incoming dependencies ($C_a$), and 5 outgoing dependencies ($C_e$), calculate Instability ($I$), Abstractness ($A$), and Normalized Distance ($D$). Interpret whether $P$ is well-designed.

Official Solution Click to reveal model answer

Step-by-Step Calculation:

  1. Abstractness ($A$): $N_a = 2, N_c = 10 \implies A = \frac{2}{10} = 0.20$
  2. Instability ($I$): $C_a = 15, C_e = 5 \implies I = \frac{C_e}{C_a + C_e} = \frac{5}{15 + 5} = \frac{5}{20} = 0.25$
  3. Normalized Distance ($D$): $D = |A + I - 1| = |0.20 + 0.25 - 1| = |0.45 - 1| = 0.55$

Architectural Interpretation:

$D = 0.55$ is significantly far from the ideal Main Sequence ($D = 0$). With very low instability ($I = 0.25$, highly depended upon by others) but very low abstractness ($A = 0.20$, mostly concrete), this package lies in the dangerous Zone of Pain: it is hard to modify because many clients depend on concrete implementations!

Module E: Architectural Patterns (Pipes & Filters, Blackboard, Apache)

From POS-exams-notes.pdf
Exam Task E.1 · Compiler with Pipes & Filters

Could you implement a compiler using Pipes & Filters? What features make the pipe architecture less suitable for a modern compiler?

Official Solution Click to reveal model answer

Can you implement it? Yes: Lexer $\to$ Parser $\to$ Semantic Analyzer $\to$ Code Generator connected via sequential streams.

Why is it less suitable for modern compilers?

  1. Global Context & Multi-Pass Optimization: Modern compilers need global symbol tables, type graphs, and multi-pass iterative optimizations that cannot stream linearly through pipes.
  2. Backward Error Propagation: If code generation fails, sending rich source-code debugging telemetry backwards through unidirectional pipes is difficult.
  3. IPC Overhead: Serializing large ASTs across OS process pipes degrades compilation throughput.
Exam Task E.2 · Blackboard Architecture Exit Condition

In the Blackboard architecture, when should the application main loop stop?

Official Solution Click to reveal model answer

Official Model Answer:

The control shell loop terminates when one of three conditions is met:

  1. A Knowledge Source posts an acceptable hypothesis whose confidence score exceeds a predefined threshold.
  2. No Knowledge Source can contribute any further increments to the blackboard (quiescence / deadlock).
  3. Predefined computational resource bounds (time limit or cycle count) are exhausted.

Module F: Analysis Patterns, Idioms & Norvig’s Criticism

From POS-exams-notes.pdf
Exam Task F.1 · Analysis Patterns vs. Design Patterns

Define in your own words the difference between Analysis Patterns and Design Patterns.

Official Solution Click to reveal model answer

Official Model Answer:

Analysis Patterns (Martin Fowler) model the problem domain and business requirements (the "What")—such as how organizations model Measurements, Quantities, and Accountability contracts.

Design Patterns (GoF) model the technical software structure and object implementation (the "How")—such as how to organize classes with Strategy, Observer, or Factory to achieve loose coupling and extensibility.

Exam Task F.2 · Peter Norvig's 16/23 Critique

What was Peter Norvig’s core critique regarding the 23 Gang of Four patterns in dynamic and functional programming languages?

Official Solution Click to reveal model answer

Official Model Answer:

In 1996, Peter Norvig proved that 16 of the 23 GoF patterns dissolve or are invisible in languages with first-class functions, closures, dynamic typing, and macros (such as Lisp, Python, and modern Java 21). Patterns like Strategy and Command simply dissolve into passing a function pointer or closure directly without declaring boilerplate interfaces and classes.

Architectural Patterns (POSA 1) 20 Points

Foundational structural patterns from Buschmann et al. Volume 1: decomposition, communication, and control.

Name it · 4 pts An architectural pattern structures distributed software systems by decoupling clients from remote servers via an intermediary service registry and marshaling layer. Clients invoke methods as if they were local, while the pattern handles binding, message serialization, and location transparency. In ≤2 words, name it.

Broker pattern (POSA 1, Chapter 2).

Key Components: Client, Client-Proxy, Broker, Server-Proxy, and Server. The Client-Proxy encapsulates IPC/network protocols and marshals parameters, while the Broker coordinates communications and resolves location transparency.

⚠️ Exam Trap: Do not confuse Broker with Proxy or Mediator. Proxy works at the design pattern level for an individual object; Broker is an architectural pattern governing entire distributed subsystem lifecycles and registration.
Select all · 5 pts Which of the following statements are TRUE regarding the Layers architectural pattern?
  • (a) In a "Strictly Layered" system, Layer J may call any Layer K as long as K < J.
  • (b) In a "Strictly Layered" architecture, Layer J may only call Layer J-1 immediately below it.
  • (c) "Relaxed Layering" improves runtime efficiency by allowing layers to bypass intermediate layers to access lower services directly.
  • (d) Cross-cutting concerns such as logging, tracing, or security always neatly fit into a single distinct horizontal layer.
  • (e) The Layers pattern makes it trivial to replace a layer implementation with another as long as the interface contract is preserved.

Correct: (b), (c), (e).

  • (a) is False: That describes Relaxed layering, not Strict layering.
  • (b) is True: Strict layering enforces that each layer only interacts with the layer immediately adjacent beneath it.
  • (c) is True: Relaxed layering avoids the performance overhead of pass-through "data forwarding" boilerplate.
  • (d) is False: Cross-cutting concerns (orthogonal services) notoriously violate pure horizontal layering; they are often handled via sidecars, aspects, or utilities.
  • (e) is True: High cohesion and low coupling between adjacent layers permit drop-in substitution.
Architecture · 6 pts Compare the Pipes and Filters pattern with the Blackboard pattern. Fill in the structural comparison table below by describing their control mechanisms, data flow direction, and best-fit problem domains.

Structural Comparison:

Attribute Pipes and Filters Blackboard
Control Flow Data-driven (push/pull through passive/active pipe) Centralized Controller evaluates Knowledge Sources
Data Flow Unidirectional stream without feedback loops Shared central repository with iterative modifications
Problem Domain Deterministic data transforms (compilers, ETL, image pipelines) Non-deterministic, heuristic search (speech recognition, AI, robotics)
⚠️ Key Architectural Pitfalls & Exam Follow-Ups:
  • Blackboard Communication Rule: Knowledge Sources NEVER communicate directly with one another. All communication is strictly mediated via reads and writes to the shared Blackboard state.
  • Blackboard 3 Exit Conditions: 1) A hypothesis reaches the target confidence threshold; 2) Quiescence/deadlock (no KS can trigger); 3) Compute/time budget exhausted.
  • Pipes & Filters for Modern Compilers: Early compilers used Pipes & Filters (lexer → parser → codegen). Modern compilers avoid pure Pipes & Filters because complex multi-pass AST optimizations, global symbol tables, and rich bidirectional error diagnostics require non-linear random access and feedback loops that linear pipes cannot accommodate.
Reorder · 5 pts Put the execution steps of a remote invocation in the Broker pattern in chronological order from first to last:
  1. A. Server-Proxy unmarshals arguments and calls the actual implementation method on the Server.
  2. B. Client invokes a method on the local Client-Proxy.
  3. C. Client-Proxy marshals the method identifier and parameters into a byte message and hands it to the Broker.
  4. D. Server computes the result, which is marshaled by Server-Proxy and sent back through the Broker to Client-Proxy.
  5. E. Broker resolves the physical network address of the target Server and forwards the payload across the network.

Correct Sequence: B → C → E → A → D

  1. B: Client initiates transparent local call on Client-Proxy.
  2. C: Client-Proxy marshals invocation into an IPC/network packet.
  3. E: Broker locates server binding via registry and routes packet.
  4. A: Server-Proxy decodes packet and dispatches to concrete Server.
  5. D: Result traverses backward: Server → Server-Proxy → Broker → Client-Proxy → Client.

Concurrency & Networking Patterns (POSA 2) 25 Points

Patterns for concurrent, networked, and real-time systems by Schmidt, Stal, Rohnert, and Buschmann.

Name it · 5 pts An event-handling pattern demultiplexes and dispatches service requests delivered concurrently to an application by one or more clients. It uses a synchronous event demultiplexer (e.g., select, poll, or epoll) running on a single thread to wait for incoming I/O events, then synchronously dispatches each event to its associated concrete Event Handler. Name it.

Reactor pattern (POSA 2, Chapter 3).

Participants: Initiation Dispatcher / Reactor, Synchronous Event Demultiplexer, Handle, and Event Handler.

⚠️ Crucial Exam Distinction: Contrast Reactor with Proactor!
• Reactor dispatches when a handle is ready for I/O (synchronous demux + synchronous read/write).
• Proactor dispatches when an asynchronous I/O operation has already completed (asynchronous operation initiated via OS kernel completion ports).
Architecture & Trade-off · 7 pts Explain the three layers of the Half-Sync / Half-Async architectural pattern. Why does it include a queueing layer between the synchronous and asynchronous layers, and what catastrophic failure occurs if this queue is unconstrained?

The Three Layers:

  1. Asynchronous Layer: Handles low-level, interrupt-driven, or asynchronous I/O events without blocking (e.g., OS network driver or Reactor dispatching packet arrivals).
  2. Queueing Layer: An intermediary thread-safe buffer (message queue) that synchronizes and stages incoming requests between async producers and sync consumers.
  3. Synchronous Layer: A pool of worker threads or processes executing long-running, blocking business logic (database transactions, business rules) safely without starving the async layer.

Purpose of the Queue: It decouples the timing, rates, and execution models of low-level async hardware/network notifications from high-level application processing.

⚠️ Catastrophic Failure Mode (Out of Memory): If producer arrival rate > consumer processing rate over sustained intervals with an unbounded queue, the queue will grow indefinitely until the JVM/OS crashes with OutOfMemoryError. The remedy is bounded queueing with backpressure or proactive shedding.
Compute & Compare · 7 pts Compare Leader/Followers against Half-Sync/Half-Async for a high-frequency trading server receiving 50,000 requests/sec. Which pattern yields lower dispatch latency, and why? Under what condition does Leader/Followers degrade severely?

Winner for Lowest Latency: Leader/Followers.

Reasoning:

  • Zero Buffer & Allocation Overhead: Leader/Followers eliminates the intermediary queue and thread context-switch penalty. The Leader thread that detects the event on the handle directly transitions to processing the request herself after promoting a Follower to become the new Leader.
  • Cache Affinity: Memory structures and socket buffers read during demux stay hot in the thread's CPU cache.
⚠️ Degradation Condition (Chain Starvation): Leader/Followers degrades severely when request handling involves long-running blocking calls or when all threads in the thread pool become busy with prior requests before a new leader can be promoted. If no follower is available to assume leadership, arriving I/O events wait unserviced in the OS socket backlog.
Code & Structure · 6 pts The Active Object pattern decouples method execution from method invocation. Complete the missing participant names and method signature blanks in the Java conceptual structure below:
public class StockTradingProxy { private Scheduler scheduler; private Servant servant; public ___________ submitOrder(Order order) { // 1. Create a concrete Method Request object MethodRequest request = new SubmitOrderRequest(servant, order); // 2. Enqueue in the Activation List via the Scheduler scheduler.enqueue(request); // 3. Return immediately without blocking return request.get___________(); } }

Filled Blanks:

  1. Return Type: Future<OrderResult> (or CompletableFuture<OrderResult>).
  2. Getter: getFuture().

Participants in Active Object:

  • Proxy: Provides the client-facing synchronous interface.
  • MethodRequest: Encapsulates method parameters and the target servant.
  • Activation List: Priority queue holding pending MethodRequests.
  • Scheduler: Runs on its own thread, deciding which MethodRequest to execute next.
  • Servant: Implements the actual business logic.
  • Future: Allows client to poll or block later to obtain the asynchronous result.

Synchronization, Service Access & Configuration 15 Points

Patterns for safe multi-threading, dynamic plugin configuration, and factory decoupling.

Name it · 5 pts A concurrency pattern solves the problem of nested self-deadlock in multi-threaded classes. It structures methods into two distinct categories: public "Interface" methods that acquire a lock and delegate to private/protected "Implementation" methods, while internal methods assume the lock is already held and never re-acquire it. In ≤3 words, name it.

Thread-Safe Interface pattern (POSA 2, Chapter 4).

How it works:

public class SafeBuffer { private final Lock lock = new ReentrantLock(); // INTERFACE METHOD: acquires lock, delegates, unlocks in finally public void put(Object item) { lock.lock(); try { put_i(item); // Call internal implementation } finally { lock.unlock(); } } // IMPLEMENTATION METHOD: assumes lock is already held by caller! protected void put_i(Object item) { // Direct state manipulation without re-locking } }
⚠️ Common Pitfall: Do not say Scoped Locking or Monitor Object. Monitor Object defines the whole class synchronization via condition variables; Thread-Safe Interface specifically deals with method-to-method internal locking boundaries without deadlock or non-recursive mutex re-entry.
Architecture · 5 pts Explain the distinction between the Acceptor and Connector roles in the Acceptor-Connector pattern. Which role acts as the passive connection factory, and which acts as the active connection initiator?

The Two Roles:

  • Acceptor (Passive Connection Factory): Waits for incoming connection requests from remote peers (e.g. listening on a server socket), accepts the connection, and instantiates/activates a concrete Service Handler to interact with the peer.
  • Connector (Active Connection Factory): Initiates an outgoing connection to a remote acceptor peer asynchronously or synchronously, and instantiates/activates a Service Handler once the connection is established.

Key Benefit: Decouples the low-level connection mechanisms (TCP, SSL, IPC) from the higher-level service processing logic encapsulated in the Service Handler.

Select all · 5 pts Which statements accurately describe the Component Configurator pattern?
  • (a) It enables an application to link and unlink its component implementations dynamically at runtime without recompiling or restarting.
  • (b) It is used by operating system kernels to load dynamic device drivers and Web servers (e.g. Apache/Nginx modules).
  • (c) It guarantees compile-time type safety across all dynamically loaded module interfaces.
  • (d) It uses a Component Repository to maintain references to all currently configured components.
  • (e) Dynamic reconfiguration can introduce security risks if shared library signatures are not verified prior to execution.

Correct: (a), (b), (d), (e).

  • (a) is True: This is the exact intent of Component Configurator.
  • (b) is True: Standard practical examples include Linux kernel modules (insmod), Apache DSO modules, and JVM plugins.
  • (c) is False: Dynamic runtime linking bypasses compile-time checks and relies on runtime interface casting / symbol resolution (dlopen/dlsym).
  • (d) is True: The Component Repository tracks active component instances and lifecycle hooks (init, suspend, resume, fini).
  • (e) is True: Malicious dynamically loaded shared objects represent arbitrary code execution vulnerabilities.

Comprehensive System Design Scenario & Traps 15 Points

A real-world architectural synthesis question testing pattern composition and trade-off evaluation.

Synthesis & Case Study · 15 pts Architectural Challenge: Ultra-Low-Latency Crypto Gateway. You are tasked with architecting a crypto exchange gateway that must sustain 80,000 concurrent WebSocket client connections, achieve sub-millisecond p99 request dispatch, and perform disk persistence without blocking incoming event streams.

Synthesize a cohesive architecture combining Reactor, Half-Sync/Half-Async, and Active Object. Provide the responsibilities of each pattern in your design and identify 3 critical architectural gotchas that would cause immediate grading deductions.

1. Architectural Pattern Composition:

Responsibilities Breakdown:

  • Reactor Layer (Non-blocking I/O): Uses OS-level event demultiplexing (e.g. epoll in Linux) to manage all 80k connections across a minimal core-pinned thread pool. It only reads bytes into memory and never executes blocking logic.
  • Half-Sync/Half-Async Queue: Acts as the shock absorber, translating high-speed asynchronous network reads into organized batches for synchronous worker execution.
  • Active Object: Decouples the order submission from disk write-ahead-logging (WAL). The order gets submitted immediately, returns a Future to the client, and disk I/O occurs on a segregated background servant thread.
⚠️ 3 Critical Deductions (Grading Traps):
  1. Blocking inside the Reactor Thread: If any database call, synchronous file logging, or complex parsing is placed inside the Reactor event handler, the entire demultiplexer freezes, halting packet receipt across tens of thousands of connections.
  2. Thread-per-Connection for 80,000 connections: Recommending Thread-per-Connection creates 80k OS threads. At standard 1MB stack size, this requires 80 GB of RAM solely for thread stacks, triggering instantaneous OutOfMemory crashes.
  3. Unbounded Inter-Layer Queue: Using an unbounded queue in the Half-Sync/Half-Async layer allows fast bursts to consume entire heap memory before worker threads can catch up. A bounded queue with explicit TCP window shrink or client backpressure is mandatory.

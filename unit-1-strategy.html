Unit 1 · Behavioral Patterns & Architectural Foundations

The Strategy Pattern

How to eliminate rigid inheritance hierarchies, encapsulate interchangeable algorithms, and enable zero-downtime runtime behavioral switching.

Core Architectural Principles GoF Category: Behavioral

The Golden Rule of Software Design: "Identify the aspects of your application that vary and separate them from what stays the same."

1. Program to an Interface

Never program to a concrete implementation. Depend on abstractions to allow frictionless polymorphism.

2. Favor Composition over Inheritance

Inheritance locks behavior at compile time. Object composition gives you dynamic runtime elasticity.

3. Open-Closed Principle (OCP)

Classes must be open for extension by introducing new strategies, but closed for modification.

1.1 The SimUDuck Evolution: The Fall of Naive Inheritance

Why standard object-oriented inheritance breaks down when systems evolve under changing business requirements.

Phase 1: The Initial Innocent Architecture
Looks Fine Initially

A duck simulation game begins with an abstract superclass Duck containing standard methods quack(), swim(), and an abstract display(). Subclasses MallardDuck and RedheadDuck inherit cleanly.

public abstract class Duck { void quack() { ... } void swim() { ... } abstract void display(); }
Phase 2: The New Feature Request & Production Bug
Catastrophic Bug

Requirement: Ducks must now fly in the simulator! A junior engineer adds void fly() directly to the Duck superclass.

💥 The Disaster: In the live customer demo, RubberDuck instances suddenly sprout wings and fly across the display! Inanimate decoy ducks fly! Behavior inherited inappropriately breaks business logic and domain modeling.
Phase 3: The Bad Band-Aid (Override with No-Ops)
Maintenance Nightmare

The team tries to "fix" it by overriding fly() in RubberDuck to do nothing: public void fly() { /* do nothing */ }.

Why this fails: As soon as 40 different duck types are added (Wooden ducks, decoy ducks, drone ducks), engineers must manually check and override dozens of methods across every class. Code duplication explodes, DRY is violated, and every superclass change risks breaking obscure subclasses.

Phase 4: The Strategy Pattern Architecture
Production Masterclass

The Breakthrough: Extract what varies (Flying & Quacking) into separate behavior interfaces. The Duck class delegates behavior execution to interface references via composition.

Zero Code Duplication Hot-Swappable at Runtime Closed for Modification

GoF Design Pattern

Architectural Role Matrix:

  • Context: Maintains a reference to a Strategy object. Communicates solely via the strategy interface. Exposes a setter allowing runtime mutability.
  • Strategy Interface: Defines an algorithm signature common to all supported algorithm variations.
  • Concrete Strategies: Implements the specific algorithm (e.g. QuickSort, CloudPayment, GPSRoute) without leaking private implementation details to Context.

DatasetSorter.java (Java 21) Generics & Functional Interfaces 
// 1. The Strategy Interface as a Functional Interface
@FunctionalInterface
public interface SortStrategy<T extends Comparable<T>> {
    void sort(List<T> items);
}

// 2. Concrete Strategy: In-place QuickSort
public final class QuickSortStrategy<T extends Comparable<T>> implements SortStrategy<T> {
    @Override
    public void sort(List<T> items) {
        if (items.size() <= 1) return;
        quickSort(items, 0, items.size() - 1);
    }
    private void quickSort(List<T> list, int low, int high) {
        if (low < high) {
            int p = partition(list, low, high);
            quickSort(list, low, p - 1);
            quickSort(list, p + 1, high);
        }
    }
    private int partition(List<T> list, int low, int high) {
        T pivot = list.get(high);
        int i = low - 1;
        for (int j = low; j < high; j++) {
            if (list.get(j).compareTo(pivot) <= 0) {
                i++;
                Collections.swap(list, i, j);
            }
        }
        Collections.swap(list, i + 1, high);
        return i + 1;
    }
}

// 3. The Context Class (Zero dependency on concrete strategies)
public class DatasetSorter<T extends Comparable<T>> {
    private SortStrategy<T> strategy;

    public DatasetSorter(SortStrategy<T> strategy) {
        this.strategy = Objects.requireNonNull(strategy, "Strategy cannot be null");
    }

    // Dynamic runtime hot-swap!
    public void setStrategy(SortStrategy<T> strategy) {
        this.strategy = Objects.requireNonNull(strategy);
    }

    public void executeSort(List<T> dataset) {
        long start = System.nanoTime();
        strategy.sort(dataset);
        long elapsed = System.nanoTime() - start;
        System.out.printf("Sorted %d elements in %.2f ms%n", dataset.size(), elapsed / 1e6);
    }
}
sorter.py (Python 3.12+) Protocol Structural Typing 
from typing import Protocol, TypeVar, List
import time

T = TypeVar("T")

# 1. Structural Strategy Abstraction via typing.Protocol
class SortStrategy(Protocol[T]):
    def sort(self, dataset: List[T]) -> None:
        """Sorts the given list in place."""
        ...

# 2. Concrete Strategy: Standard Timsort
class TimSortStrategy:
    def sort(self, dataset: List[T]) -> None:
        dataset.sort()

# 3. Concrete Strategy: Custom Reverse Sort
class ReverseSortStrategy:
    def sort(self, dataset: List[T]) -> None:
        dataset.sort(reverse=True)

# 4. Context Class
class DatasetProcessor:
    def __init__(self, strategy: SortStrategy[T]) -> None:
        self._strategy = strategy

    def set_strategy(self, strategy: SortStrategy[T]) -> None:
        self._strategy = strategy

    def process(self, data: List[T]) -> None:
        t0 = time.perf_counter()
        self._strategy.sort(data)
        elapsed = (time.perf_counter() - t0) * 1000
        print(f"Processed {len(data)} items via {self._strategy.__class__.__name__} in {elapsed:.3f}ms")

# Example Usage
if __name__ == "__main__":
    data = [42, 12, 88, 3, 99, 15]
    processor = DatasetProcessor(TimSortStrategy())
    processor.process(data)
    
    # Dynamic runtime switch to Reverse Strategy
    processor.set_strategy(ReverseSortStrategy())
    processor.process(data)
DuckSimulator.java Complete GoF Pattern Architecture 
// Behavior Interfaces
public interface FlyBehavior { void fly(); }
public interface QuackBehavior { void quack(); }

// Concrete Fly Implementations
public class FlyWithWings implements FlyBehavior {
    public void fly() { System.out.println("Flapping biological wings at high altitude!"); }
}
public class FlyNoWay implements FlyBehavior {
    public void fly() { System.out.println("<< Grounded: Cannot fly >>"); }
}
public class FlyRocketPowered implements FlyBehavior {
    public void fly() { System.out.println("🚀 Mach 3 Jet Propulsion Activated!"); }
}

// Abstract Duck Superclass (Context)
public abstract class Duck {
    protected FlyBehavior flyBehavior;
    protected QuackBehavior quackBehavior;

    public void performFly() { flyBehavior.fly(); }
    public void performQuack() { quackBehavior.quack(); }
    public void swim() { System.out.println("All ducks float on water!"); }
    public abstract void display();

    // Hot-swap setters
    public void setFlyBehavior(FlyBehavior fb) { this.flyBehavior = fb; }
    public void setQuackBehavior(QuackBehavior qb) { this.quackBehavior = qb; }
}

// Concrete Duck Subclasses
public class MallardDuck extends Duck {
    public MallardDuck() {
        flyBehavior = new FlyWithWings();
        quackBehavior = new Quack();
    }
    public void display() { System.out.println("I am a real Mallard Duck."); }
}

public class ModelDuck extends Duck {
    public ModelDuck() {
        flyBehavior = new FlyNoWay(); // Model initially can't fly
        quackBehavior = new Quack();
    }
    public void display() { System.out.println("I am a futuristic Model Duck."); }
}

How the Fortune 500 and open-source infrastructure leverage the Strategy Pattern daily.

Java Standard Library: Comparator

Collections.sort(List, Comparator) is the canonical Strategy pattern. The list sorting algorithm is the Context, while the custom ordering comparator is the Strategy passed dynamically at call time.

Java SDK Standard
🐧

Linux Virtual File System (VFS)

The Linux kernel treats all storage (ext4, NTFS, Btrfs, NFS) through a generic struct file_operations table of function pointers. When you call read(), the kernel delegates to the mounted filesystem's strategy.

Cloud Payment Gateway Routing

Payment processors like Uber or Airbnb route transactions through Stripe, Adyen, or PayPal dynamically. If Stripe experiences high latency in Europe, an algorithmic router switches to Adyen in 5ms without application restarts.

1.7 Architecture Decision Matrix: Strategy vs. Alternatives

Never pick a pattern blindly. Compare trade-offs against Template Method and State.

Pattern Core Intent Mechanism Coupling Degree Runtime Switching?
Strategy Swap whole interchangeable algorithms Composition / Delegation (has-a) Loose (Depends only on interface) ✅ YES (Dynamic)
Template Method (Unit 2) Keep algorithm skeleton, override steps Inheritance / Polymorphism (is-a) Tight (Tied to base class hierarchy) ❌ NO (Compile-time)
State Pattern Alter behavior as internal object state mutates Composition (Context changes state object) Moderate (States often know about transitions) ✅ YES (Automatic)

🎯 Professor Gotcha #1: The Strategy Object Explosion

"What happens when a high-scale system has an explosion of Strategy objects? How can an architect prevent catastrophic memory exhaustion?"

The Architectural Problem: If 1,000,000 Duck or Sorter instances each instantiate a brand new FlyWithWings or QuickSortStrategy object, the JVM/runtime allocates millions of redundant objects, triggering severe Garbage Collector pauses and heap bloat.

The 3 Exam-Grade Solutions:

  1. Stateless Strategies via Flyweight Pattern: If a Strategy contains no mutable instance fields (it only executes algorithmic logic on data passed to it), it can be made a stateless Singleton / Flyweight. All 1,000,000 contexts reference a single shared instance in memory.
  2. First-Class Lambdas & Method References: In modern Java (Integer::compareTo) or Python (lambda x: x.id), strategies are passed as pure function references without allocating heavyweight class instances.
  3. Strategy Factory (Unit 8): Cache and manage strategy lifecycles behind a centralized Factory to prevent ad-hoc allocation.
🎯 Professor Gotcha #2: The Data Access & Privacy Leak Dilemma

"GoF states a Strategy gets data by (A) parameter arguments or (B) Context reference passed to Strategy. What happens if the data required by Strategy is NOT public on Context? How do you solve this without violating Encapsulation?"

The Dilemma: If Context makes its internal private fields public via getters just so a Strategy can inspect them, Information Hiding is completely destroyed for all other outside clients!

The 3 Architectural Remedies:

  1. Narrow Interface (Interface Segregation Principle): Define a restricted interface (e.g. ContextInspectable) exposing only the specific fields needed by the Strategy. Context implements this interface. Context passes this typed strictly as ContextInspectable. Outside clients cannot see these methods.
  2. Data Transfer Object (DTO) / Parameter Object: Context extracts and bundles only the required data slice into an immutable DTO and passes it into strategy.execute(dto).
  3. Package-Private Visibility (Java) / Friend Classes (C++): Place the Context and Concrete Strategies in the same internal package, keeping access methods package-private so outside packages cannot access them.

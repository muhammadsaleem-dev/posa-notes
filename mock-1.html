Part 1 · Core Written Questions (From Page 1)

15 Points Total
Question 6: Which of the OOP principles does decorator primarily follow: Inheritance or composition and briefly explain why? 5 Points
Model Answer

Primary Principle: Composition (Object Composition over Class Inheritance)

  1. Composition Provides Dynamic Extension: The Decorator pattern dynamically attaches behavior at runtime by holding a reference to the wrapped component instance (protected Component component;) and delegating method invocations to it.
  2. Inheritance is Purely for Type Conformance: Subclassing the Component class is done solely for interface matching / subtyping—so the decorator can substitute wherever a Component is expected. It does NOT inherit behavior from the superclass.
  3. Prevents Subclass Explosion: Avoids the $2^N$ static subclass combinations created by naive inheritance (e.g., Starbuzz coffee).
⚠️ Professor Gotcha: Answering "Inheritance" or simply "both" without clarifying that inheritance is only used for type matching while composition provides the actual functional extension results in up to a 50% deduction.
Question 7: What is the main task/role of the model in MVC? 5 Points
Model Answer
  1. Encapsulates Business Data & Domain State: Holds all domain data, business logic, calculations, constraints, and persistence rules.
  2. Complete UI Independence: Contains zero UI code and has no direct reference to any Views or Controllers. It is testable in isolation.
  3. Observer Subject Role: Acts as the Subject in the Observer pattern. When its internal state changes (triggered by Controller actions), it notifies registered View observers, which then pull the updated data.
⚠️ Professor Gotcha: Stating that the Model directly updates or renders the View is an automatic point deduction. The Model merely notifies observers; the View queries the Model!
Question 8: How does the Strategy Pattern differ from the Template Method Pattern? 5 Points
Model Answer
Dimension Strategy Pattern Template Method Pattern
Mechanism Object Composition & Delegation Class Inheritance & Subclassing
Binding Time Dynamic at Runtime (hot-swappable algorithms via setter) Static at Compile-Time (bound through subclass instantiation)
Algorithm Granularity Swaps the entire algorithm via an interface Fixes the skeletal invariant flow; subclasses override specific steps
Design Principle Favor composition over inheritance Hollywood Principle ("Don't call us, we'll call you!")

GoF Quote: "Template Method uses inheritance to vary parts of an algorithm. Strategy uses composition to vary the entire algorithm."

Exercise 2 · Legacy Integration with Adapter & Iterator

16 Points (2 + 4 + 6 + 4)
Exam Scenario: You want to use a legacy Quicksort library that takes Vector as part of its API: 
Vector quicksort(Vector vector)
However, in your code you want to use a List implementation by calling: 
List quicksort(List list)
to sort a list and after sorting you want to print all elements of the list.

API Provided on Exam Sheet: 
Vector: public Vector(Collection c), Enumeration elements()
Enumeration: boolean hasMoreElements(), Object nextElement()
Iterator: boolean hasNext(), Object next()
1. Which (two) patterns can you use to simplify your implementation? 2 Points
Model Answer
  1. Adapter Pattern: To adapt the legacy Vector / Enumeration interfaces into the modern List / Iterator interfaces without modifying the legacy library code.
  2. Iterator Pattern: To sequentially traverse and print all elements of the sorted list uniformly.
2. Draw the UML of these patterns! 4 Points
Model Answer 
[Client] ----> <> Iterator<Object>
                     ^
                     | (implements)
      EnumerationIteratorAdapter ----> <> Enumeration (Adaptee)
      - enumeration: Enumeration       + hasMoreElements(): boolean
      + hasNext(): boolean             + nextElement(): Object
      + next(): Object
3. Please write down the source code of your implementation of: List quicksort(List list). Do not forget to print all elements of the list! 10 Points (6 + 4)
Model Answer 
// 1. Adapter: Adapting legacy Enumeration to modern Iterator
public class EnumerationIteratorAdapter implements Iterator<Object> {
    private final Enumeration enumeration;

    public EnumerationIteratorAdapter(Enumeration enumeration) {
        this.enumeration = enumeration;
    }

    public boolean hasNext() {
        return enumeration.hasMoreElements();
    }

    public Object next() {
        return enumeration.nextElement();
    }
}

// 2. Client implementation
public List quicksort(List list) {
    if (list == null) return null;

    // Adapt modern List into legacy Vector using Vector(Collection c)
    Vector legacyVector = new Vector(list);

    // Call the legacy sorting library
    Vector sortedVector = LegacyLibrary.quicksort(legacyVector);

    // Adapt sorted Vector back to modern List using EnumerationIteratorAdapter
    List resultList = new ArrayList();
    Enumeration en = sortedVector.elements();
    Iterator it = new EnumerationIteratorAdapter(en);

    while (it.hasNext()) {
        resultList.add(it.next());
    }

    // Print all elements of the sorted list (as explicitly instructed!)
    Iterator printIt = resultList.iterator();
    System.out.print("Sorted Elements: ");
    while (printIt.hasNext()) {
        System.out.print(printIt.next() + " ");
    }
    System.out.println();

    return resultList;
}
⚠️ Professor Gotcha: Forgetting to print all elements in the final loop results in an automatic 4-point deduction! The prompt explicitly said: "Do not forget to print all elements of the list!"

Exercise 3 · Strategy Pattern & Open-Closed Principle (OCP)

16 Points (8 + 4 + 4)
Exam Scenario: You have to implement a flexible way to sort Collections using different algorithms such as QuickSort or MergeSort.
You can assume that the List contains a list of numbers and that you can call:
• Vector quicksort(Vector vector)
• List mergesort(List list)
1. Fill the gaps indicated by the symbol => in the Java implementation below. 8 Points
Model Answer 
public interface Sorter {
    List sort(List list);
}

public class QuickSorter implements Sorter {
    public List sort(List list) {
        Vector v = new Vector(list);
        Vector sorted = LegacyLibrary.quicksort(v);
        return new ArrayList(sorted);
    }
}

public class MergeSorter implements Sorter {
    public List sort(List list) {
        return MergeSortLib.mergesort(list);
    }
}

public class SortContext {
    private Sorter sorter;
    public SortContext(Sorter sorter) { this.sorter = sorter; }
    public void setSorter(Sorter sorter) { this.sorter = sorter; }
    public List executeSort(List list) { return sorter.sort(list); }
}
2. Draw the UML diagram and identify the design pattern used. 4 Points
Model Answer

Design Pattern Used: Strategy Pattern

[SortContext] o----> <> Sorter
                     + sort(List): List
                            ^
              +-------------+-------------+
              |                           |
       [QuickSorter]               [MergeSorter]
       + sort(List): List          + sort(List): List
3. Does the pattern (fully?!) adhere to the OCP (Open Closed Principle)? (Please provide explanation!) 4 Points
Model Answer
  • Why it adheres to OCP: The system is open for extension because new sorting algorithms (e.g., HeapSorter, TimSorter) can be introduced simply by implementing Sorter without modifying existing code. It is closed for modification because existing sorter classes remain untouched.
  • Does it FULLY adhere? NO, not unconditionally.
    • It only fully adheres if the client uses Dependency Injection or an abstract factory to inject the sorter.
    • If the client code uses a hardcoded if-else or switch(algoType) statement to instantiate concrete sorters (e.g. if (type.equals("quick")) return new QuickSorter()), then adding a new sorter requires modifying that selection code, partially violating OCP!

Exercise 4 · Template Method Pattern Refactoring

14 Points (3 + 6 + 2 + 3)
Exam Scenario: You want to refactor the code of a quicksort library so that it supports flexible sorting of student objects based on a configurable criteria (e.g., age or name). Assume the source code looks as follows: 
public List sort(List list) {
    // ... long list of quicksort logic ...
    if (arr[j] < pivot) {  // Crucial hardcoded comparison
        // ...
    }
}
A developer wants to use the Template Method pattern for this task.
1. Comment on the choice of the template pattern! 3 Points
Model Answer

The choice of Template Method is sub-optimal and rigid:

  • Template Method relies on class inheritance. To sort students by age, name, or GPA, developers must create concrete subclasses: AgeQuickSorter, NameQuickSorter, GpaQuickSorter.
  • This causes subclass explosion and ties the sorting criteria statically to the class hierarchy at compile-time.
  • The Strategy Pattern (like Java's Comparator<Student>) is far superior: it parameterizes the comparison via object composition dynamically at runtime without subclassing.
2. Document your refactoring: (a) How many primitiveOperations do you need? (b) Provide reasonable names for the primitiveOperation(s) and TemplateMethod. (c) Describe which parts of the source code go where. 11 Points (6 + 2 + 3)
Model Answer
  1. (a) How many primitiveOperations do you need? (6 Points)
    Exactly 1 primitiveOperation is needed: a comparison hook to compare two elements against each other (e.g. boolean isLessThan(T a, T b) or int compare(T a, T b)).
  2. (b) Reasonable names for the methods: (2 Points)
    • TemplateMethod: public final List sort(List list) (declared final so subclasses cannot alter the invariant skeletal algorithm).
    • primitiveOperation: protected abstract boolean isLessThan(Object a, Object b).
  3. (c) Which parts of the source code go where? (3 Points)
    • TemplateMethod: Contains all invariant divide-and-conquer logic: pivot selection, partitioning loop, recursion boundaries (`p`, `r`, `q`), and array swapping.
    • primitiveOperation: Strictly contains the variant comparison statement replacing if (arr[j] < pivot) with if (isLessThan(arr[j], pivot)).

Exercise 5 · Composite Pattern & Arithmetic Expression Trees

14 Points (4 + 4 + 6)
Expression Given on Exam Sheet:

3 + 4 * (5 - 6 * 2 / (x + y))

1. Identify the composite structure in the following expression and draw the corresponding tree! 4 Points
Model Answer 
                  (+)  [Root]
                 /   \
               (3)   (*)
                    /   \
                  (4)   (-)
                       /   \
                     (5)   (/)
                          /   \
                        (*)   (+)
                       /   \  /  \
                     (6)  (2)(x) (y)

• Composite Nodes: Operators (+, -, *, /) holding sub-expression children.
• Leaf Nodes: Operands (3, 4, 5, 6, 2, x, y) holding numeric literals or variables.

2. Fill all missing arrows in the Composite UML! 4 Points
Model Answer 
<> Component
+ evaluate(): double
       ^
       | (generalization / inheritance)
+------+---------------------------+
|                                  |
Leaf (Number/Variable)      Composite (Operator)
- value: double             - left: Component
+ evaluate(): double        - right: Component
                            + evaluate(): double
                            + add(c: Component)
                            + remove(c: Component)
                            + getChild(i: int): Component
                                   |
                                   +-----> points back to Component (aggregation 1..*)
3. Explain how the Composite pattern enables to compute the expression in your own words using the (completed) UML diagram! 6 Points
Model Answer
  1. Uniform Evaluation: Clients invoke root.evaluate() on the top-level Component without querying whether it is a leaf or a composite node.
  2. Recursive Evaluation: When evaluate() is called on an operator (Composite), it recursively calls left.evaluate() and right.evaluate(), applying its arithmetic operator (e.g. $+$ or $*$) to the returned scalar values.
  3. Terminal Base Case: When evaluate() reaches a Leaf, it immediately returns its literal number or looks up the variable's value.
  4. Consolidation of Conditionals: Zero conditional branches (no if (node instanceof ...) or switch) are needed across client code.

Exercise 6 · Singleton Implementation & SOLID Violations

12 Points (6 + 4 + 2)
1. Fill the gaps indicated by the symbol -> in the following code to implement a Singleton instance of a class with reflection protection. 6 Points
Model Answer 
public class Singleton {
    // -> Gap 1: Private static instance variable
    private static Singleton instance;

    // -> Gap 2: Private constructor with reflection defense
    private Singleton() {
        if (instance != null) {
            throw new RuntimeException("Singleton instance already exists! Reflection forbidden.");
        }
    }

    // -> Gap 3: Public static synchronized access method
    public static synchronized Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}
2. Which of the SOLID principle/s does Singleton violate? 4 Points
Model Answer
  • Single Responsibility Principle (SRP): Singleton has two distinct responsibilities: (1) its domain business responsibility, and (2) managing its own global lifecycle and enforcing instance uniqueness.
  • Dependency Inversion Principle (DIP): Clients call the concrete static Singleton.getInstance() directly, tightly coupling caller code to a concrete class rather than an abstraction/interface. This makes automated mocking and unit testing nearly impossible.
3. Can you give an example where we can use Singleton pattern in an application? 2 Points
Model Answer
  • Application configuration registry / properties loader.
  • Database connection pool or thread pool manager.
  • Centralized system logger (e.g. Logger.getInstance()).

Exercise 7 · Pattern Criticism & Functional Python Idioms

12 Points (4 + 8)
1. "Patterns are signs of weakness in programming languages." (Mark Dominus) — provide at least two of his arguments! 4 Points
Model Answer
  1. Workarounds for Missing Language Features: Design patterns often arise as manual boilerplate workarounds for limitations in static early OOP languages (like C++ and Java 1.0) that lacked first-class functions, closures, dynamic dispatch, or macros.
  2. Patterns Evaporate into Syntax: When a programming language introduces modern features, the pattern ceases to be an architectural design structure and becomes basic language syntax (e.g. Strategy becomes a lambda argument, Iterator becomes yield, Visitor becomes multi-methods).
2. Python Quicksort with Lambdas: (a) Explain how comp1 and comp2 sort in ascending/descending order and provide a substitute for Template Method. (b) Why do we not need the Strategy object in this code? 8 Points (4 + 4)
Model Answer
comp1 = lambda a, b: a <= b
comp2 = lambda a, b: a >= b
print(qsort([1, 9, 0, 5, 6], comp1)) # Ascending: [0, 1, 5, 6, 9]
print(qsort([1, 9, 0, 5, 6], comp2)) # Descending: [9, 6, 5, 1, 0]
  • Ascending vs Descending Order: comp1 moves elements smaller than or equal to pivot to the left partition, sorting ascending. comp2 moves elements greater than or equal to pivot to the left partition, sorting descending.
  • Substitute for Template Method: The invariant quicksort structure (recursion, partitioning) is kept intact in quicksort(), while the variant comparison is injected without any class inheritance or subclassing.
  • Why do we not need the Strategy object? In Python, functions are first-class citizens. They can be passed directly as arguments, stored in variables, and invoked anonymously. There is zero need to wrap algorithms inside boilerplate Strategy interfaces and concrete classes!

Exercise 8 · System Architecture: Banking Application

18 Points (9 + 9)
Exam Scenario: Imagine you are the lead engineer of a team implementing a banking application enabling:
  • Account Management: Option to create different types of accounts (savings, current, business, etc.).
  • Payment System & Wire Transfers: Wire transfer of money between accounts, including external banks and third-party gateways (e.g. PayPal).
  • Real-time Notifications: Alerts for account activities (transaction alerts, balance updates) when one of those activities is completed.
1. Provide a list of patterns you would use for your architecture! 2. Provide a short explanation why each pattern is helpful! 18 Points (9 + 9)
Model Architecture Blueprint
Design Pattern Subsystem Applied Why the Pattern is Helpful
Factory Method / Abstract Factory Account Creation Encapsulates creation of different account types (SavingsAccount, CurrentAccount, BusinessAccount) without coupling client code to concrete classes, adhering to OCP.
Adapter Pattern Payment Integration Adapts incompatible external APIs (e.g., PayPal REST API, SWIFT wire protocols) to match the bank's standard internal PaymentGateway interface.
Observer Pattern Notification Alerts Decouples account business operations from notification channels. When a transaction completes or balance changes, the account broadcasts notifications to registered observers (SMS, Email, Push).
Command Pattern Wire Transfer Engine Encapsulates each transaction as an executable object (TransferCommand), enabling transaction queues, audit logs, validation, and compensating rollback (undo).
Strategy Pattern Interest & Fee Engine Enables interchangeable, runtime-configurable fee calculation and interest rate policies without modifying core Account entities.
Decorator Pattern Account Features Dynamically attaches optional features to accounts (e.g. overdraft protection, premium insurance, foreign currency wallets) without subclass explosion.

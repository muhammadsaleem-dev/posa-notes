Question 6 · Unit 9 (Decorator) 5 Points

Which of the OOP principles does decorator primarily follow: Inheritance or composition and briefly explain why?

Official Solution & Rubric Model Answer

Primary Principle: Composition (Object Composition over Class Inheritance)

  1. Composition Provides Dynamic Behavior: The Decorator pattern dynamically attaches behavior at runtime by holding a reference to the wrapped component instance (protected Component component;) and delegating client method invocations to it.
  2. Inheritance is Purely for Type Conformance: Subclassing the Component class is done solely for subtyping/interface matching—so the decorator can transparently substitute for the component. It does NOT inherit its functional behavior from the parent.
  3. Prevents Subclass Explosion: Avoids the $2^N$ static subclass combinations created by naive inheritance.
⚠️ Professor Gotcha: Answering "Inheritance" or simply "both" without clarifying that inheritance is only for type matching while composition provides the actual functional extension costs up to 50% deduction.
Question 7 · Unit 11 (MVC) 5 Points

What is the main task/role of the model in MVC?

Official Solution & Rubric Model Answer
  1. Encapsulates Business Data & Domain State: Holds all domain data, business logic, entities, invariants, and calculations.
  2. Complete UI Independence: Contains zero presentation or GUI references. It is completely decoupled and testable in isolation.
  3. Observer Subject Role: Acts as the Subject in the Observer pattern. When its state changes, it notifies registered views, which pull the updated state.
⚠️ Professor Gotcha: Never state that the Model directly updates or renders the View. The Model merely notifies observers; the View queries the Model!
Question 8 · Unit 1 & Unit 2A 5 Points

How does the Strategy Pattern differ from the Template Method Pattern?

Official Solution & Rubric Model Answer
Dimension Strategy Pattern Template Method Pattern
Mechanism Object Composition & Delegation Class Inheritance & Subclassing
Binding Time Dynamic at Runtime (swappable via setter) Static at Compile-Time (bound through subclass)
Algorithm Granularity Swaps the entire algorithm via an interface Fixes skeletal invariant flow; overrides variant steps
Key Principle Favor composition over inheritance Hollywood Principle ("Don't call us, we'll call you!")
⚠️ GoF Quote: "Template Method uses inheritance to vary parts of an algorithm. Strategy uses composition to vary the entire algorithm."

Exercise 2 · Legacy Integration with Adapter & Iterator

16 Points (2 + 4 + 6 + 4)

You want to use a legacy Quicksort library using Vector quicksort(Vector vector), but your application code must call List quicksort(List list) and print all sorted elements.

Exercise 2 Tasks & Complete Solution

Legacy API Provided on Exam Sheet:

Vector quicksort(Vector vector)
// Legacy Vector has: Vector(Collection c), Enumeration elements()
// Enumeration has: boolean hasMoreElements(), Object nextElement()
// Iterator has: boolean hasNext(), Object next()
Solution (Part 1, 2, 3) Model Answers & Java Source Code

1. Which (two) patterns can you use to simplify your implementation? (2 Points)

  • Adapter Pattern: To adapt the legacy Vector / Enumeration interfaces to the modern List / Iterator interfaces without modifying legacy code.
  • Iterator Pattern: To sequentially traverse and print the sorted elements uniformly without exposing internal data structures.

2. Draw the UML of these patterns! (4 Points)

[Client] --> <<interface>> Iterator<Object> { +hasNext(), +next() }
                      ^
                      |
        EnumerationIteratorAdapter ----> <<interface>> Enumeration { +hasMoreElements(), +nextElement() }

3. Java Source Code Implementation of List quicksort(List list): (6 + 4 Points)

// 1. Adapter: Adapting Enumeration to Iterator
public class EnumerationIteratorAdapter implements Iterator<Object> {
    private final Enumeration enumeration;
    public EnumerationIteratorAdapter(Enumeration enumeration) {
        this.enumeration = enumeration;
    }
    public boolean hasNext() {
        return enumeration.hasMoreElements();
    }
    public Object next() {
        return enumeration.nextElement();
    }
}

// 2. Client Quicksort Implementation
public List quicksort(List list) {
    if (list == null) return null;

    // Adapt modern List into legacy Vector using Vector(Collection c)
    Vector legacyVector = new Vector(list);

    // Call the legacy sorting library
    Vector sortedVector = LegacyLib.quicksort(legacyVector);

    // Adapt sorted Vector back to modern List using EnumerationIteratorAdapter
    List resultList = new ArrayList();
    Enumeration en = sortedVector.elements();
    Iterator it = new EnumerationIteratorAdapter(en);

    while (it.hasNext()) {
        resultList.add(it.next());
    }

    // Print all elements of the sorted list (as explicitly instructed!)
    Iterator printIt = resultList.iterator();
    System.out.print("Sorted Elements: ");
    while (printIt.hasNext()) {
        System.out.print(printIt.next() + " ");
    }
    System.out.println();

    return resultList;
}
⚠️ Professor Gotcha: Forgetting to print all elements in the final loop results in an automatic 4-point deduction! Always read the prompt instruction: "Do not forget to print all elements of the list!"

Exercise 3 · Strategy Pattern & Open-Closed Principle (OCP)

16 Points (8 + 4 + 4)

Implement a flexible way to sort Collections using different algorithms (QuickSort, MergeSort) and analyze whether it (fully?!) adheres to OCP.

📷 Original Exam Sheet Scan · Exercise 3 (Pages 3, 4, 5) Click to inspect

Exercise 3 Tasks & OCP Analysis

Official Solution & Rubric Model Code, UML & OCP Proof

1. Fill the gaps in the Java implementation: (8 Points)

public interface Sorter {
    List sort(List list);
}

public class QuickSorter implements Sorter {
    public List sort(List list) {
        Vector v = new Vector(list);
        Vector sorted = LegacyLib.quicksort(v);
        // adapt back to List
        return new ArrayList(sorted);
    }
}

public class MergeSorter implements Sorter {
    public List sort(List list) {
        return MergeSortLib.mergesort(list);
    }
}

2. Draw the UML diagram and identify the pattern: (4 Points)

Pattern Used: Strategy Pattern. Encapsulates sorting algorithms into interchangeable classes conforming to Sorter.

3. Does the pattern (fully?!) adhere to the OCP (Open Closed Principle)? (4 Points)

  • Why it adheres to OCP: The system is open for extension because a new sorting algorithm (e.g. HeapSorter, TimSorter) can be introduced simply by implementing Sorter without modifying existing code. It is closed for modification because existing sorters remain untouched.
  • Does it FULLY adhere? NO, not unconditionally! Full adherence depends entirely on how the client selects and instantiates the concrete sorter:
    • If the client or factory uses a hardcoded switch(algoType) or if-else chain, adding a new sorter requires modifying that selection logic, thereby violating OCP!
    • It only fully adheres if selection is decoupled via Dependency Injection, reflection, or a configuration registry.

Exercise 4 · Template Method Pattern Refactoring

14 Points (3 + 6 + 2 + 3)

Refactor a quicksort library supporting hardcoded < comparison to flexibly sort Student objects by age or name.

📷 Original Exam Sheet Scan · Exercise 4 (Pages 5 & 6) Click to inspect

Exercise 4 Tasks & Architecture Refactoring

Official Solution & Rubric Model Commentary & Refactoring Plan

1. Comment on the choice of the Template Pattern: (3 Points)

The choice of Template Method is sub-optimal compared to the Strategy pattern.

  • Template Method relies on class inheritance. To sort students by age, name, or GPA, one must create separate subclasses: AgeQuickSorter, NameQuickSorter, GpaQuickSorter.
  • This causes subclass explosion and ties the sorting criteria statically to the class hierarchy at compile-time.
  • In contrast, the Strategy pattern (like Java's Comparator<Student>) achieves this dynamically at runtime via object composition without creating any subclasses of the sorter.

2. Document your Refactoring: (11 Points)

  1. (a) How many primitiveOperations do you need? (6 Points)
    Exactly 1 primitiveOperation is needed: a comparison hook, e.g. boolean isLessThan(Object a, Object b) or int compare(Object a, Object b).
  2. (b) Reasonable names for the methods: (2 Points)
    • TemplateMethod: public final List sort(List list) (marked final to prevent overriding invariant skeletal flow).
    • PrimitiveOperation: protected abstract boolean isLessThan(Object a, Object b).
  3. (c) Which parts of the source code go where? (3 Points)
    • TemplateMethod: Contains the entire invariant divide-and-conquer algorithm: partitioning logic, recursion, array indexing, and element swapping.
    • PrimitiveOperation: Strictly contains the variant comparison statement replacing if (arr[j] < pivot) with if (isLessThan(arr[j], pivot)).

2. Composite UML Arrows & Roles: (4 Points)

  • Leaf (NumericOperand, Variable) generalizes (inherits from) Component.
  • Composite (BinaryOperator) generalizes (inherits from) Component.
  • Composite has a directed aggregation / composition reference pointing to Component with multiplicity 1..* (or left, right: Component).

3. How the Composite pattern computes the expression: (6 Points)

The Composite pattern enables uniform recursive evaluation via polymorphism:

  1. Clients invoke root.evaluate() on the top-level Component without querying whether it is a leaf or a composite.
  2. When evaluate() is called on an operator (Composite), it recursively calls left.evaluate() and right.evaluate(), applying its operator (e.g. $+$ or $*$) to the returned scalar values.
  3. When evaluate() reaches a Leaf, it immediately returns its literal number or looks up the variable's value.
  4. Result: Zero conditional branches (no if (node instanceof ...)) across the entire client codebase.

Exercise 6 Tasks & Architectural Evaluation

Official Solution & Rubric Model Java Code & SOLID Analysis

1. Java Code Implementation with Reflection Guard: (6 Points)

public class Singleton {
    // 1. Static reference to hold the single instance
    private static Singleton instance;

    // 2. Private constructor with reflection defense
    private Singleton() {
        if (instance != null) {
            throw new RuntimeException("Singleton instance already exists! Reflection forbidden.");
        }
    }

    // 3. Thread-safe global accessor
    public static synchronized Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}

2. Which of the SOLID principle/s does Singleton violate? (4 Points)

  • Single Responsibility Principle (SRP): The class has two responsibilities: (1) its domain business responsibility, and (2) managing its own global lifecycle and enforcing instance uniqueness.
  • Dependency Inversion Principle (DIP): Clients call the concrete static Singleton.getInstance() directly, tightly coupling caller code to a concrete class rather than an interface. This makes automated mocking and unit testing nearly impossible.

3. Valid Industrial Use Cases for Singleton: (2 Points)

  • Configuration registry / properties manager for an application.
  • Database connection pool or thread pool manager.
  • Hardware logger or printer spooler manager.

Exercise 7 · Pattern Criticism & Functional Python Idioms

12 Points (4 + 8)

Analyze Mark Dominus's critique and explain why Python first-class function quicksort eliminates the need for Strategy objects.

📷 Original Exam Sheet Scan · Exercise 7 (Pages 9 & 10) Click to inspect

Exercise 7 Tasks & Functional Analysis

Official Solution & Rubric Model Arguments & Python Code Analysis

1. "Patterns are signs of weakness in programming languages" (Mark Dominus): (4 Points)

  1. Compensating for Missing Abstractions: Design patterns often arise as manual, boilerplate workarounds for limitations in static, early OOP languages (like C++ and Java 1.0) that lacked first-class functions, closures, dynamic dispatch, or macros.
  2. Patterns Evaporate into Syntax: When a programming language introduces modern features, the pattern ceases to be an architectural design structure and becomes basic language syntax (e.g. Strategy becomes a lambda argument, Iterator becomes yield, Visitor becomes multi-methods).

2. Python Quicksort with First-Class Comparison Functions: (8 Points)

  • Ascending vs Descending Order: Passing comp1 = lambda a, b: a <= b yields ascending order because the partition loop places smaller elements to the left. Passing comp2 = lambda a, b: a >= b inverts the partition comparison, producing descending order.
  • Substitute for Template Method: The skeletal quicksort flow (divide-and-conquer recursion) remains completely invariant in quicksort(), while the comparison criteria is parameterized without any class inheritance or subclassing.
  • Why do we not need the Strategy object? In Python, functions are first-class citizens. They can be passed directly as arguments, stored in variables, and invoked anonymously. There is zero need to wrap algorithms inside boilerplate Strategy interfaces and concrete classes!

Exercise 8 Architecture Blueprint & Pattern Justifications

Official Solution & Rubric Architecture Patterns & Rationale
Design Pattern System Subsystem Architectural Justification & Value
Factory Method / Abstract Factory Account Management Encapsulates creation of different account types (SavingsAccount, CurrentAccount, BusinessAccount) without coupling caller code to concrete classes, adhering to OCP.

Official Exam Question 6 · Unit 9 (Decorator) 5 Points

Which of the OOP principles does decorator primarily follow: Inheritance or composition and briefly explain why?

Official Solution & Grading Rubric Prof. Dr. Jörg Schäfer Model Answer

Primary Principle: Composition (Object Composition over Class Inheritance)

Official Model Explanation:

  1. Primary Mechanism (Composition): The Decorator pattern dynamically attaches additional responsibilities to an object at runtime. The decorator maintains a reference to the wrapped component instance (protected Component component;) and delegates client method invocations to this component, optionally executing pre- or post-processing behavior.
  2. Role of Inheritance (Type Conformance Only): While the Decorator subclasses the abstract Component class, it does so solely for type matching (subtyping)—to ensure the decorator can stand in transparently wherever the original component is expected (conforming to the Liskov Substitution Principle). It does not inherit its functional behavior from the parent class.
  3. Avoidance of Class Explosion: By favoring dynamic composition over static compile-time inheritance, Decorator avoids the combinatorial explosion of subclasses (e.g., $2^N$ subclass combinations in Starbuzz Coffee with milk, mocha, soy, whip).
⚠️ Professor Gotcha & Deduction Trap: Answering "Inheritance" or simply "both" without explicitly distinguishing between type conformance (subtyping via inheritance) and behavioral extension (delegation via composition) results in up to 50% deduction. You MUST state that behavior is obtained via composition!
Grading Breakdown (5 Pts):
• 2 pts: Clear identification of Composition as primary principle.
• 2 pts: Clarification that inheritance is restricted to interface/type conformance.
• 1 pt: Explanation of runtime flexibility / preventing subclass explosion.
Official Exam Question 7 · Unit 11 (MVC) 5 Points

What is the main task/role of the model in MVC?

Official Solution & Grading Rubric Prof. Dr. Jörg Schäfer Model Answer

Official Model Answer (3 Core Pillars):

  1. Encapsulation of Application Domain State & Business Logic: The Model represents the enterprise domain, holding all application data, entities, business rules, calculations, constraints, and persistence logic.
  2. Presentation Independence: The Model is completely independent of the User Interface. It contains zero UI code and has no direct reference to any Views or Controllers. It remains completely testable in isolation.
  3. Observer Subject Role (Notification Mechanism): The Model acts as the Subject in the Observer pattern. When its internal state is modified (via Controller commands), it notifies registered View observers (notifyObservers()). The Views then pull the updated data directly from the Model.
⚠️ Professor Gotcha & Deduction Trap: Stating that the Model "updates the View" or "renders UI components" (e.g., calling view.render()) is an immediate deduction. In classical GoF / Reenskaug MVC, the Model is completely passive regarding presentation: it broadcasts an abstract change notification, and the View pulls data!
Grading Breakdown (5 Pts):
• 2 pts: Encapsulating domain state, entities, and business logic.
• 2 pts: Complete decoupling/independence from UI presentation.
• 1 pt: Acting as the Subject/Observable notifying registered Views upon state change.
Official Exam Question 8 · Unit 1 & Unit 2A 5 Points

How does the Strategy Pattern differ from the Template Method Pattern?

Official Solution & Grading Rubric Prof. Dr. Jörg Schäfer Model Answer

The canonical distinction is captured in the Gang of Four principle: "Template Method uses inheritance to vary parts of an algorithm. Strategy uses composition to vary the entire algorithm."

Dimension Strategy Pattern (Unit 1) Template Method Pattern (Unit 2A)
Fundamental Mechanism Object Composition & Delegation Class Inheritance & Subclassing
Binding Time Dynamic at Runtime (strategy can be hot-swapped dynamically via setter) Static at Compile-Time (bound through subclass instantiation)
Algorithm Granularity Swaps the entire algorithm behind an interface (e.g. FlyBehavior) Fixes the skeletal invariant flow; subclasses override specific hook/primitive steps
Inversion of Control Client/Context controls execution and explicitly invokes strategy interface Hollywood Principle: "Don't call us, we'll call you!" Base class calls child hooks
Class Coupling Loose coupling to an abstract interface Tight coupling to base class hierarchy
⚠️ Professor Gotcha & Deduction Trap: Simply saying "Strategy uses interfaces and Template Method uses abstract classes" is superficial and receives partial credit. You MUST articulate that Strategy delegates the entire interchangeable algorithm via composition, whereas Template Method enforces an invariant skeleton and delegates only variant sub-steps via inheritance.
Grading Breakdown (5 Pts):
• 2 pts: Composition vs Inheritance mechanism distinction.
• 1 pt: Runtime dynamic binding vs compile-time static binding.
• 2 pts: Whole algorithm encapsulation vs skeletal invariant flow with step hooks.

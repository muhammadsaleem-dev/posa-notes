Unit 7 · Macro Architecture & Package Design

Package Principles & Main Sequence Metrics

Master Robert C. Martin's 6 package principles (cohesion & coupling), the Acyclic Dependencies Principle (ADP), and quantitative package metrics: Instability ($I$), Abstractness ($A$), and Distance from the Main Sequence ($D$).

1

The 6 Packaging Principles

Cohesion & Coupling Granularity
Package Cohesion Principles (What belongs inside a package): • REP (Reuse/Release Equivalence Principle): "The granule of reuse is the granule of release." Code must be tracked with release numbers and documentation so consumers know when to upgrade.
• CCP (Common Closure Principle): "Classes that change together are packaged together." (The SRP of packages). Minimizes the number of packages affected when requirements change.
• CRP (Common Reuse Principle): "Classes that are not used together should not be packaged together." (The ISP of packages). Prevents consumers from depending on things they don't need.
Package Coupling Principles (How packages depend on each other): • ADP (Acyclic Dependencies Principle): "Allow no cycles in the package dependency graph." The package dependency structure must form a Directed Acyclic Graph (DAG).
• SDP (Stable Dependencies Principle): "Depend in the direction of stability." A package should only depend on packages that are more stable than itself ($I_{\text{target}} \le I_{\text{source}}$).
• SAP (Stable Abstractions Principle): "A package should be as abstract as it is stable." Stable packages must be abstract so they can be extended without modification; unstable packages should be concrete.
CRITICAL EXAM DRILL Two Strategies to Break Dependency Cycles (ADP)
Strategy 1: Invert Dependency via DIP

If Package A depends on Package B, and Package B needs a class in Package A, extract an interface into Package B that Package A implements. The dependency arrow reverses, eliminating the cycle.

Strategy 2: Extract a Shared Package

Identify the mutual classes that cause the cyclic dependency and extract them into a new third package, Package C. Both Package A and Package B depend on Package C, restoring an acyclic DAG.

Robert C. Martin's Package Metrics

Quantitative Stability & Abstractness
FORMULAS & DEFINITIONS Computing $Ca$, $Ce$, $I$, $A$, and $D$

Instability Metric ($I$)

$$I = \frac{Ce}{Ca + Ce} \quad (0 \le I \le 1)$$ • $Ca$ (Afferent Coupling): Number of external classes that depend on classes inside this package (incoming arrows).
• $Ce$ (Efferent Coupling): Number of classes inside this package that depend on external classes (outgoing arrows).
• $I = 0$: Maximally stable (dependent upon by many, depends on none).
• $I = 1$: Maximally unstable (depends on many, no dependents).

Abstractness Metric ($A$)

$$A = \frac{Na}{Nc} \quad (0 \le A \le 1)$$ • $Na$: Number of abstract classes and interfaces in the package.
• $Nc$: Total number of classes (concrete + abstract + interfaces) in the package.
• $A = 0$: Purely concrete package.
• $A = 1$: Purely abstract package (only interfaces/abstract classes).

Normalized Distance from Main Sequence ($D$)

$$D = |A + I - 1| \quad (0 \le D \le 1)$$ • The Main Sequence line satisfies: $A + I = 1$.
• Packages close to $D = 0$ are well-balanced between stability and abstractness.
• Packages far from the line ($D \to 1$) fall into architectural pathology zones.

3

The Zone of Pain vs. The Zone of Uselessness

Main Sequence Vector Chart
📐 Canonical Architecture: Figure 7.1 The Main Sequence Diagram ($A$ vs $I$)
Zone of Pain ($A \approx 0, I \approx 0$)

Packages in this zone are maximally stable and maximally concrete. Many external packages depend on them, yet they have no abstractions. Modifying them breaks everything. Acceptable ONLY for non-volatile utility foundations (e.g. java.lang.String).

Zone of Uselessness ($A \approx 1, I \approx 1$)

Packages in this zone are maximally abstract and maximally unstable. They contain pure abstract classes and interfaces, but nobody depends on them. Represents architectural over-engineering or abandoned designs.

Core Exam Practice & Model Solutions

Direct Question → Answer Format
Question 1: Explain the Acyclic Dependencies Principle (ADP) 3 Points

Explain the Acyclic Dependencies Principle (ADP). Why are dependency cycles problematic, and what are two strategies to break them?

Model Answer:
  1. Principle: The dependency graph of packages must contain no cycles; it must be a Directed Acyclic Graph (DAG).
  2. Problem: Cycles create the "Morning After Syndrome". If Package A depends on Package B, and B depends on A, any change in A forces a re-build and re-test of B, which in turn triggers a re-build of A. The packages merge into one monolithic build unit, making independent testing and releasing impossible.
  3. Two Cycle-Breaking Strategies:
    • Dependency Inversion Principle (DIP): Introduce an interface in the caller's package and invert the dependency arrow.
    • Extract Shared Package: Move the classes both packages depend upon into a new shared package.
Question 2: Computing Package Metrics ($I, A, D$) 6 Points

A package billing contains 10 classes in total ($Nc = 10$), of which 2 are abstract ($Na = 2$). There are 6 external classes depending on classes in billing ($Ca = 6$), and classes in billing depend on 2 external classes ($Ce = 2$). Compute $I$, $A$, and $D$, and interpret whether this package is well-balanced!

Model Answer:
  1. Instability ($I$): $$I = \frac{Ce}{Ca + Ce} = \frac{2}{6 + 2} = \frac{2}{8} = 0.25$$ (The package is relatively stable; 75% of dependencies are incoming).
  2. Abstractness ($A$): $$A = \frac{Na}{Nc} = \frac{2}{10} = 0.20$$ (The package is largely concrete; 20% abstract).
  3. Distance from Main Sequence ($D$): $$D = |A + I - 1| = |0.20 + 0.25 - 1| = |0.45 - 1| = |-0.55| = 0.55$$
  4. Architectural Interpretation: $D = 0.55$ indicates that the package is located significantly below the Main Sequence line, drifting toward the Zone of Pain. Because it is highly stable ($I = 0.25$), the Stable Abstractions Principle (SAP) mandates that it should be more abstract (closer to $A \approx 0.75$). To improve balance, more interfaces should be introduced to decouple external clients from concrete billing classes.

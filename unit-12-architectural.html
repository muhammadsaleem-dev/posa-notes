PILLAR 1 OF 8 · INTENT & MOTIVATION

Macro Architectural Structures

Unlike micro GoF class design patterns, POSA architectural patterns organize the entire topology of a subsystem. Pipes & Filters partitions data stream transformations into independent stages, while Blackboard enables opportunistic problem solving where no deterministic algorithm exists.

Pipes & Filters Intent

Provide a structure for systems that process a stream of data. Encapsulate each transformation step in a reusable filter component linked by directional pipes.

Blackboard Intent

Enable diverse specialized expert modules (Knowledge Sources) to collaboratively discover a solution to non-deterministic problems via a shared repository.

PILLAR 4 OF 8 · DESIGN PRINCIPLES

Deterministic vs Non-Deterministic Control

Feed-Forward Streams (Pipes & Filters)

Processing is strictly deterministic. Data moves unidirectionally through independent filters without feedback loops or cycles.

Opportunistic Heuristics (Blackboard)

Processing is non-deterministic. The sequence of Knowledge Source activation is determined dynamically at runtime based on confidence scores.

High Filter Reusability

Filters can be recombined into new pipelines like Unix CLI utilities (cat | grep | sort | uniq) without changing filter source code.

PILLAR 5 OF 8 · IMPLEMENTATION MECHANICS

Active vs Passive Filters

StreamPipeline.java · Java Streams & Active Filters
// Active Filter: Runs in its own thread, reading from inPipe and writing to outPipe
public class DecryptingFilter implements Runnable {
    private final BlockingQueue<ByteBuffer> inPipe;
    private final BlockingQueue<ByteBuffer> outPipe;

    public void run() {
        while (!Thread.currentThread().isInterrupted()) {
            ByteBuffer rawChunk = inPipe.take(); // Pulls when ready (blocks on empty)
            ByteBuffer decrypted = decrypt(rawChunk);
            outPipe.put(decrypted); // Pushes downstream (blocks on full backpressure)
        }
    }
}
PILLAR 6 OF 8 · COSTS & TRADE-OFFS

Architectural Costs & Bottlenecks

✅ Architectural Benefits
  • High concurrency: Active filters execute concurrently across multi-core processors.
  • Pluggable recombining: Easy to insert new compression or encryption filters.
  • Blackboard solves complex AI tasks where algorithmic steps are unknown.
⚠️ Architectural Liabilities
  • Data transformation overhead: Serialization and deserialization at each pipe stage.
  • Lowest common denominator data format (e.g. byte streams or JSON strings).
  • Blackboard synchronization bottlenecks around shared central memory.

Prof. Schäfer Exam Traps: Feedback Loops

🚨 Frankfurt UAS Exam Trap #1: Can Pipes & Filters have Feedback?

Question: "Can a filter in Pipes & Filters pass data backwards to an upstream filter?"
Model Answer: No! The pure Pipes and Filters architectural pattern strictly mandates feed-forward acyclic streaming. Introducing backward feedback loops destroys pipeline parallelism, creates deadlocks in bounded buffers, and violates filter autonomy.

Industry Standard: Apache Kafka, Unix Shell Pipelines, Apache Web Server Hooks.

● Stage 01 · Pipes & Filters Topologies

Stream Processing & The Pipeline Topology

Pipes and Filters partitions high-throughput data processing into self-contained, independent filter components. Pipes connect the output of one filter to the input of the next without the filters being aware of each other's existence.

🧠 Key Takeaways: Stream Processing Axioms
Filter Isolation

A filter knows nothing of upstream or downstream stages. It reads from its input pipe and writes to its output pipe.

Parallel Pipeline Execution

Active filters execute on separate threads, enabling true multi-core parallel streaming across chunks.

Backpressure Management

Bounded pipes prevent fast upstream filters from overwhelming slower downstream consumers.

● Stage 02 · The Blackboard Pattern

The Blackboard Pattern: Opportunistic Heuristic Solving

What happens when no deterministic pipeline algorithm exists? In speech recognition, radar tracking, or medical diagnostics, multiple incomplete hypotheses must be evaluated concurrently. The Blackboard Pattern coordinates independent Knowledge Sources through a shared memory hub.

1. The Blackboard (Central Repository)

A structured global memory partitioned into hypothesis levels (e.g., Acoustic Waveform $\to$ Syllables $\to$ Words $\to$ Complete Sentence). It holds partial solutions and confidence scores.

2. Knowledge Sources (Domain Experts)

Specialized modules that know how to transform data at one level to a higher level. Knowledge Sources never communicate with each other directly! They only inspect and modify the Blackboard.

3. The Controller (Orchestrator)

Monitors the state of the Blackboard. Whenever new data is written, the Controller evaluates which Knowledge Sources qualify to execute and schedules the one with the highest confidence rating.

● Stage 04 · Production Case Study

Case Study: Apache Web Server Hooks

The Apache HTTP Server is a classic real-world implementation of the Pipes and Filters architecture combined with Chain of Responsibility. Each incoming HTTP request flows through a predetermined sequence of processing phases:

mod_authz_core.c · Apache Hook Registration
// Apache 2.4 Hook Registration Pipeline
static void register_hooks(apr_pool_t *p) {
    // Phase 1: Translate URI to server filename
    ap_hook_translate_name(translate_user_uri, NULL, NULL, APR_HOOK_MIDDLE);

    // Phase 2: Authentication & Authorization Filters
    ap_hook_check_authn(verify_jwt_token, NULL, NULL, APR_HOOK_FIRST);
    ap_hook_check_authz(check_role_permissions, NULL, NULL, APR_HOOK_MIDDLE);

    // Phase 3: Content Generation (The Core Handler)
    ap_hook_handler(render_static_html, NULL, NULL, APR_HOOK_LAST);

    // Phase 4: Logging Filter
    ap_hook_log_transaction(log_access_metrics, NULL, NULL, APR_HOOK_REALLY_LAST);
}

Exam Drill 1 Why is the Blackboard pattern considered non-deterministic, and how does its control loop differ fundamentally from Pipes and Filters? (10 Exam Points)

Model Answer (Prof. Schäfer 1.0 Standard):

Pipes and Filters (Deterministic): Control flow is fixed, predetermined, and feed-forward. Data always flows in an immutable sequence from Filter 1 to Filter 2 to Filter 3. Given the same input stream, filters execute in the identical order every time.

Blackboard (Non-Deterministic): Control flow is opportunistic and dynamic. Multiple independent Knowledge Sources monitor the central Blackboard. The Controller inspects the Blackboard state and schedules whichever Knowledge Source produces the highest confidence rating at that instant. Execution sequencing varies from run to run based on partial hypotheses.

Exam Drill 2 Can a filter in a Pipes & Filters architecture send feedback data backwards to an upstream filter? Explain why or why not. (6 Exam Points)

Model Answer:

No! The Pipes and Filters architectural pattern strictly forbids backward feedback loops for two fundamental reasons:

  1. Deadlock Hazard: Pipes are implemented as bounded buffers. If Filter B waits for Filter A while simultaneously trying to push feedback into a full pipe connected back to Filter A, both filters deadlock.
  2. Destruction of Filter Independence: Introducing backward feedback couples upstream filters to the internal processing states of downstream filters, violating autonomy and preventing parallel pipelining.
Exam Drill 3 Compare Active Filters with Passive Filters in Pipes and Filters architectures. (4 Exam Points)

Model Answer:

  • Active Filter: Runs on its own dedicated OS thread (or process). It actively pulls data from the input pipe and pushes results to the output pipe in a continuous loop. Enables multi-threaded concurrency.
  • Passive Filter: Does not possess its own thread. It acts as a passive function invoked by an adjacent active component (e.g. called via a pull method invocation or pushed via a callback).

Unit 12 · Macro-Architectural Patterns (POSA 1)

Pipes & Filters and The Blackboard Pattern

“Each pattern depends both on the smaller patterns it contains, and on the larger patterns within which it is contained.” — Christopher Alexander

System-level macro structures for data processing: streaming pipelines without feedback versus centralized opportunistic blackboard systems for non-deterministic AI problem solving.

1

12.3 Pipes and Filters Architecture

Sequential streaming transformations with independent processing stages.

POSA Intent: Provide a structure for systems that process a stream of data. Each processing step is encapsulated in a filter component. Data is passed through pipes between adjacent filters.

Ingredients:

  • Data Source: Generates initial stream (e.g. file, network socket, sensors).
  • Pipe: Directional conduit transferring data from one filter to another, managing buffering and backpressure.
  • Filter: Enriches, refines, or transforms data. Can be active (runs its own thread, pulls/pushes) or passive.
  • Data Sink: Target consumer (database, display, output file).

12.4 The Blackboard Pattern

Opportunistic problem-solving for non-deterministic domains.

POSA Intent: Useful for problems where no deterministic algorithm exists (speech recognition, AI routing, protein folding). Multiple diverse specialized modules collaborate to discover a solution incrementally.

The 3 Participants:

  1. Blackboard: The central global memory containing partial solutions, hypotheses, and problem state.
  2. Knowledge Sources (KS): Distinct, independent experts. Each KS evaluates the blackboard and adds new inferences when its preconditions are satisfied. KS never talk to each other!
  3. Controller: An orchestrator that assesses the state of the blackboard and schedules which eligible Knowledge Source executes next.

12.7 Case Study: Apache Web Server Hooks

Apache HTTP Server organizes request servicing into a pipeline of processing phases: URI-to-filename translation $\to$ Header parsing $\to$ Authentication $\to$ Authorization $\to$ Content generation $\to$ Logging. Modules register hook functions with the core server, creating a flexible hybrid of Pipes & Filters, Chain of Responsibility, and Component Configurator.

12.8 Questions for Self-Study

Exam Drill Why is the Blackboard pattern considered non-deterministic, and how does its control loop differ fundamentally from Pipes and Filters?

In Pipes and Filters, the control and data flow is fixed, deterministic, and feed-forward: data flows from filter A directly to filter B in a predetermined pipeline.

In Blackboard, there is no predetermined sequence. Multiple Knowledge Sources evaluate the shared hypotheses simultaneously. The Controller opportunistically selects whichever Knowledge Source provides the highest confidence score based on the current state. The order of execution varies from run to run depending on partial inferences.

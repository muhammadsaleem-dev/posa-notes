Architectural Patterns: Pipes & Filters, Blackboard & Microkernel

Master high-level architectural schemas: sequential stream processing in Pipes & Filters (Active vs. Passive), opportunistic heuristic problem solving in Blackboard, and extensible operating system kernels in Microkernel.

1

Architectural Pattern Profiles

System-Level Schemas
1. Pipes & Filters Pattern: "Provides a structure for systems that process a stream of data. Each processing step is encapsulated in a filter component. Data is passed through pipes between adjacent filters."
Core Trait: Completely decoupled processing stages; filters have zero mutual knowledge and do not share state.
2. Blackboard Pattern: "Useful for problems for which no deterministic solution strategies are known. Several specialized subsystems (knowledge sources) assemble their partial knowledge on a shared central data store (blackboard)."
Core Trait: Non-deterministic, opportunistic problem solving guided by a central Control component.
3. Microkernel Pattern: "Applies to software systems that must be able to adapt to changing system requirements. It separates a minimal functional core from extended customer-specific parts and external servers."
2

Pipes & Filters: Active vs. Passive Filters

Control & Concurrency Topologies
FILTER MECHANICS Active vs. Passive Filter Architecture
Active Filter (Own Thread)

Runs in its own autonomous execution thread. It actively pulls data from the input pipe, processes it, and actively pushes data to the output pipe. Pipes between active filters must be synchronized queues or buffers (e.g. blocking FIFO).

Passive Filter (Caller Thread)

Does not run an independent thread. It is triggered by an external caller either pushing data into it (push filter) or calling read() on it to pull data out (pull filter, like java.io.FilterInputStream).

The Blackboard Pattern: The 3 Participants

Opportunistic Problem Solving
BLACKBOARD TRIAD Blackboard, Knowledge Sources & Control
Participant Role & Responsibility Key Constraint
Blackboard Central structured repository holding current problem state, hypotheses, and partial solutions. The only shared medium through which knowledge sources communicate.
Knowledge Sources (KS) Autonomous specialist modules capable of reading state and contributing partial solutions to the blackboard. Never communicate directly with each other! Strict isolation.
Control Component Monitors blackboard changes and dynamically evaluates which Knowledge Source is best suited to act next. Contains the heuristic strategy determining termination or scheduling.

Core Exam Practice & Model Solutions

Direct Question → Answer Format
Question 1: Active vs. Passive Filters in Pipes & Filters 4 Points

Explain the difference between an Active Filter and a Passive Filter in the Pipes and Filters architectural pattern!

Model Answer:
  • Active Filter: Executes as an independent autonomous thread of control. It runs a loop pulling incoming data from an input pipe and pushing transformed results to an output pipe. Requires thread-safe, synchronized buffer pipes.
  • Passive Filter: Has no autonomous thread. Its execution is driven by an external component invoking its methods: either the upstream neighbor pushes data into it (Push Filter), or the downstream neighbor pulls data from it (Pull Filter).
Question 2: The Three Core Participants of the Blackboard Pattern 5 Points

Name and explain the three core participants of the Blackboard architectural pattern and describe how knowledge sources communicate!

Model Answer:
  1. Blackboard: The central shared memory structure containing the domain state, input problem data, and evolving partial solution hypotheses.
  2. Knowledge Sources (KS): Distinct, independent specialist agents (e.g. acoustic, lexical, phonetic in speech recognition) that inspect the blackboard and update it with partial solutions.
  3. Control: The orchestrator that evaluates the current blackboard state and decides which Knowledge Source should be triggered next.
  4. Communication Rule: Knowledge sources never communicate directly with one another. All communication is decoupled through mutations on the shared Blackboard.

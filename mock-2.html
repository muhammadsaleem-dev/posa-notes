Behavioral & Structural Patterns 25 Points

Strategy Pattern · 5 pts In the SimUDuck simulator, explaining why declaring fly() in the abstract superclass Duck created architectural rot. How did the Strategy pattern resolve the forces?

The Architectural Rot:

Adding fly() to the base Duck class assumed that all ducks fly. Inanimate rubber ducks and decoy ducks inherited flight capability. Overriding fly() in subclasses with empty no-op bodies duplicated code across 50 subclasses, violating the DRY Principle and creating high fragility.

The Strategy Resolution:

Encapsulated flying behavior into an independent interface FlyBehavior (with implementations like FlyWithWings, FlyNoWay). Duck now has-a FlyBehavior (composition over inheritance) and delegates performFly() to the strategy instance. Flying behavior can be changed dynamically at runtime.

Template vs Strategy · 5 pts Compare the Template Method pattern with the Strategy pattern regarding the Hollywood Principle and resilience to runtime change.

Template Method: Relies on inheritance. The superclass enforces the algorithm skeleton (Hollywood Principle: “Don’t call us, we’ll call you”) and calls subclass hook operations. Inflexible at runtime because inheritance is statically bound at compile time.

Strategy Pattern: Relies on object composition and delegation. The entire algorithm is encapsulated in a separate object. Highly resilient to change because the strategy object can be swapped dynamically while the program is running.

Command Pattern · 5 pts A home automation remote control uses a MacroCommand containing [LightOnCommand, StereoOnCommand, AirConditionerOnCommand]. In what order must the undo() method execute these commands, and why?

Exact Execution Order: Reverse chronological order: AirConditionerOnCommand.undo() $\to$ StereoOnCommand.undo() $\to$ LightOnCommand.undo().

Reasoning: Commands often have state dependencies where later operations depend on the preconditions established by earlier operations. Reversing the sequence ensures that dependent resources are safely rolled back without violating state invariants (implemented via a Last-In-First-Out stack).

Composite Pattern · 5 pts How does the Composite pattern eliminate instanceof type-checking loops when traversing hierarchical tree structures?

Both individual leaf elements (MenuItem) and nested branches (Menu) implement a common uniform component interface (MenuComponent). When the client calls menu.print(), polymorphic dispatch takes over: leaves print themselves, while composites iterate over their child list and call child.print() recursively. The client requires zero conditional logic.

JUnit Architecture · 5 pts In JUnit 3.8.x (Cook’s Tour), identify the roles of TestCase, TestSuite, and TestResult.
  • TestCase (Command & Template Method): Encapsulates individual test execution commands, sequencing setUp() $\to$ runTest() $\to$ tearDown().
  • TestSuite (Composite): Aggregates Test instances so running one test or running 5,000 tests looks completely identical to test runners.
  • TestResult (Collecting Parameter): Passed across the entire composite tree to accumulate test success, failure, and error counts without coupling tests to runners.

SOLID Principles & Package Metrics 25 Points

Liskov Substitution · 5 pts State Barbara Liskov’s formal substitution definition. Why does Square extends Rectangle violate it?

Formal Definition: If $S$ is a subtype of $T$, then objects of type $T$ may be replaced with objects of type $S$ without altering any of the desirable properties of the program (correctness, task performed).

Violation: A Rectangle contract guarantees that calling setWidth(w) alters only the width while leaving height unchanged. A Square subclass breaks this postcondition by modifying both width and height simultaneously. Client code asserting area calculations breaks unexpectedly.

Package Metrics Calculation · 10 pts Full Mathematical Derivation: Package com.ecommerce.billing has 6 incoming dependencies from external packages ($C_a = 6$) and depends on 2 external utility packages ($C_e = 2$). The package contains 4 interfaces ($N_a = 4$) and 16 total classes ($N_c = 16$).

Calculate:
1. Instability Metric ($I$)
2. Abstractness Metric ($A$)
3. Normalized Distance from the Main Sequence ($D$)
4. Diagnose whether the package suffers from the Zone of Pain or Zone of Uselessness.

1. Instability:

$$I = \frac{C_e}{C_a + C_e} = \frac{2}{6 + 2} = \frac{2}{8} = \mathbf{0.25}$$

2. Abstractness:

$$A = \frac{N_a}{N_c} = \frac{4}{16} = \mathbf{0.25}$$

3. Normalized Distance from Main Sequence:

$$D = |A + I - 1| = |0.25 + 0.25 - 1| = |-0.50| = \mathbf{0.50}$$

4. Architectural Diagnosis:

Since $A + I = 0.50 < 1$, the package is drifting into the Zone of Pain. Because it is highly stable ($I = 0.25$, heavily depended upon by 6 packages), having only $25\%$ abstractness ($A = 0.25$) makes it too concrete and rigid to modify easily without breaking clients. The team should extract more interfaces to raise $A$ closer to $0.75$.

Package Cohesion Rules · 5 pts Differentiate between the Common-Reuse Principle (CRP) and the Common-Closure Principle (CCP).
  • Common-Closure Principle (CCP): Classes that change together should be packaged together. It minimizes release frequency by ensuring a requirement change affects only one package (Package-level Single Responsibility).
  • Common-Reuse Principle (CRP): Classes that aren’t reused together should not be packaged together. It prevents clients from being forced to depend on classes they don’t need (Package-level Interface Segregation).
Breaking Package Cycles · 5 pts How does an architect resolve a dependency cycle between Package A and Package B that violates the Acyclic Dependencies Principle (ADP)?

Two Standard Architectural Solutions:

  1. Apply Dependency Inversion (DIP): If Class in A depends on Class in B, and Class in B depends on Class in A, create an interface inside Package A. Have the class in Package B implement that interface, inverting the dependency and breaking the cycle.
  2. Extract to a Third Package: Move the mutually dependent classes into a new shared package C that both A and B depend upon.

Creational & Flexibility Patterns 20 Points

Abstract Factory · 5 pts How does the Abstract Factory pattern enforce that families of products are never accidentally mixed (e.g. NY pizza dough with Chicago pizza sauce)?

The client code only interacts with the generic PizzaIngredientFactory interface. A concrete factory instance (NYPizzaIngredientFactory) is injected into the client. Because the concrete factory manufactures all related components (dough, sauce, cheese) internally, the client has no way to mix and match individual ingredients from competing families.

Singleton Concurrency · 5 pts What critical bug does the volatile keyword prevent in Java's Double-Checked Locking Singleton?

It prevents compiler and CPU instruction reordering. Without volatile, the JVM can allocate memory, assign the reference to the static variable, and execute constructor initialization out of order. A concurrent thread reading the reference outside the lock could observe a non-null reference to an uninitialized object.

Decorator Streams · 5 pts Analyze the code: new LineNumberInputStream(new BufferedInputStream(new FileInputStream("test.txt"))). Identify the component and decorators, and state which principle this exemplifies.

FileInputStream is the Concrete Component (reads raw bytes). BufferedInputStream and LineNumberInputStream are Concrete Decorators augmenting buffering and line tracking. This exemplifies the Open-Closed Principle (OCP): adding behavior dynamically without altering the underlying byte-reading class.

Adapter Pattern · 5 pts Why does an Object Adapter offer superior flexibility over a Class Adapter?

An Object Adapter uses composition to hold an Adaptee reference, allowing a single adapter to adapt not just the Adaptee class, but all of its existing and future subclasses. A Class Adapter binds statically to a single concrete Adaptee via inheritance and cannot adapt subclasses.

Decoupling, MVC & GenAI Synthesis 25 Points

Observer Memory Leak · 5 pts Explain the "Lapsed Listener Problem" in the Observer pattern and how it causes memory leaks in managed runtimes (Java/C#).

The Subject holds a strong reference to all registered Observers in its internal listener list. If an observer goes out of application scope without explicitly calling removeObserver(), the Subject's strong reference keeps the observer reachable in the GC root graph, preventing garbage collection. Solution: Use WeakReference for listener registration.

Pipes vs Blackboard · 5 pts Contrast Pipes & Filters with the Blackboard pattern regarding control flow and state management.
  • Pipes & Filters: Feed-forward deterministic data stream. Data flows through pipes between adjacent filters without a shared global state.
  • Blackboard: Opportunistic non-deterministic search. Multiple independent Knowledge Sources iteratively inspect and update a centralized global repository under the guidance of a Controller.
MVC Patterns · 5 pts Name the three design patterns that collaborate within classic Model-View-Controller.
  1. Observer: Model acts as Subject, View acts as Observer.
  2. Strategy: Controller acts as the input handling Strategy for the View.
  3. Composite: View elements (windows, buttons, panels) are structured as composite trees.
Architectural Synthesis & GenAI · 10 pts Unit 16 Case Study: IoT Weather Station with AI Assistance. You are instructing an AI coding assistant to scaffold an IoT Weather Station application. Synthesize the architectural pattern composition (Quantity, Observer, MVC) and state 2 architectural guardrails to prevent the AI from generating brittle code.

1. Architectural Pattern Composition:

  • Quantity Pattern: Sensor readings (temperature, pressure, wind speed) are modeled as immutable Value Objects bound to explicit Unit enums (preventing unit confusion bugs).
  • Observer Pattern: WeatherStationModel publishes domain events whenever valid sensor quantities arrive.
  • Model-View-Controller: Separates sensor ingest and calculation (Model) from mobile/web displays (View) and calibration REST endpoints (Controller).
⚠️ 2 Critical Architectural Guardrails:
  1. Enforce Interface Segregation (ISP): Prevent the AI from creating a single monolithic God Interface combining sensor reading, persistence, and UI display. Demand narrow client-specific interfaces.
  2. Strict Immutability on Quantities: Require that Quantity objects have no setter methods to prevent the AI from mutating shared value state across observer threads.

“Don’t call us, we’ll call you!” — The Hollywood Principle (Inversion of Control)

In traditional top-down procedural programming, low-level modules call high-level utility functions. Under the Hollywood Principle, control flow is completely inverted (IoC):

  • The high-level abstract class declares a final template method that dictates when each step executes.
  • Subclasses provide specific step implementations, but never dictate the sequence or timing.
  • This eliminates dependency rot and prevents fragile callback loops.
Stage 2

The Command Pattern: Modeling Verbs as Objects

Decouple the sender of a request (Invoker) from the object that actually executes the business action (Receiver).

Gang of Four Specification

“Encapsulate a request as an object, thereby letting you parameterize clients with different requests, queue or log requests, and support undoable operations.”

Invoker: Remote control button or UI menu item. Only calls command.execute(). Zero knowledge of Receiver.
Command Interface: Declares execute() and optional undo().
Receiver: The actual appliance (Light, Stereo, GarageDoor) performing the real work.

Stage 4

Macro Commands, Multi-Level Undo & Thread Pools

Executing composite command sequences and decoupling work items in concurrent thread pools.

CRITICAL EXAM RULE: Reverse Undo Ordering

When executing a MacroCommand (Composite Pattern), commands execute in forward order (1 $\to$ 2 $\to$ 3). However, when calling undo(), the sequence MUST strictly execute in reverse order (3 $\to$ 2 $\to$ 1) using a LIFO Stack or reverse iterator. Otherwise, state dependencies will be corrupted!

🎯 Official Exam Gotcha: Dumb vs. Smart Commands

"How tightly coupled is a concrete Command to its Receiver? Can a Command execute logic without any Receiver?"

Two Architectural Styles exist:

  1. Dumb Commands (Standard GoF): Command only delegates to Receiver (receiver.action()). Coupling between Command and Receiver is tight, but the Invoker remains 100% decoupled from Receiver.
  2. Smart / Self-Contained Commands: Command implements the complete business logic directly without any Receiver. Used in distributed RPC messaging and standalone calculation jobs.

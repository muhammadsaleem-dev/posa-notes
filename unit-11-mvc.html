Unit 11 · Compound Architectural Patterns

Case Study: Model-View-Controller (MVC)

“A pattern only works, fully, when it deals with all the forces that are present in the system.” — Christopher Alexander

Invented by Trygve Reenskaug for Smalltalk-80, MVC is the mother of all compound patterns. Learn how Observer, Composite, and Strategy collaborate to create clean user interfaces.

1

11.3 The MVC Triad

1. The Model

Holds all domain data, business logic, state rules, and persistence. The Model has zero knowledge of the user interface. It broadcasts state changes via the Observer pattern.

2. The View

The visual representation of the Model. Observes the Model for updates and renders elements. Delegates user input events (button clicks, keystrokes) to the Controller.

3. The Controller

Translates user gestures into actions on the Model. It serves as the Strategy for the View, dictating how inputs are interpreted into domain operations.

The 3 Patterns Inside MVC

1. Observer Pattern (Model $\to$ View)

Keeps the View decoupled from the Model. Multiple different views (graphs, text tables, mobile cards) can observe the same single Model simultaneously.

2. Strategy Pattern (View $\to$ Controller)

The Controller is the Strategy for the View. To change how the UI reacts to inputs (e.g., read-only mode vs editable mode), swap the View's Controller.

3. Composite Pattern (Nested Views)

GUI screens are composite trees of windows, panels, scroll-panes, and buttons. When the top-level View updates, render commands traverse the composite hierarchy.

11.5 MVC in Web & Enterprise Architectures

On the Web (Spring MVC, Django, Rails), the HTTP request-response cycle slightly modifies classic desktop MVC: The Controller intercepts HTTP requests via a DispatcherServlet, queries the database Model, and selects a template View to render HTML back across the wire.

11.7 Questions for Self-Study

Exam Drill Why does the Model have zero knowledge of the View in a well-architected MVC system?

By ensuring the Model has no direct references to UI components, the Model achieves complete independence from presentation technologies.

The same business Model can be reused across a web app, a mobile app, a command-line interface, and automated unit test suites without any changes. Furthermore, the Model can be tested headlessly in CI/CD without spinning up GUI frameworks.

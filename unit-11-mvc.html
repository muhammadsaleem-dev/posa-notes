Unit 11 · Architectural & Compound Patterns 2026 Syllabus: Unit 10 (Part 2)

Case Study: Model-View-Controller (MVC)

Master the archetypal compound pattern: the Model (domain state & business logic), the View (rendering & display), and the Controller (user gesture translation). Understand how Observer, Strategy, and Composite collaborate.

⚡ Executive Summary Case Study MVC: The Foundational Compound Pattern
Collapse Expand

“Separate domain representation (Model) from presentation (View) and user input interpretation (Controller).”

🎯 The Triad of Coordinated Patterns

MVC is a compound pattern combining: Observer (Model broadcasts state updates to Views), Strategy (Controller is the swappable event strategy for the View), and Composite (nested View GUI widgets).

→ Business logic in the Model remains 100% UI-agnostic.
🕵️‍♂️ Active MVC vs. Passive MVC

In Active MVC, the Model updates independently (e.g. background threads, web sockets) and notifies Views directly. In Passive MVC, the Controller queries the Model and updates the View explicitly.

→ Crucial distinction tested on architectural exams.

The MVC Triad Specification

Smalltalk-80 Architectural Heritage
1. The Model: Holds all application data, domain state, and core business logic. It has ZERO awareness of the View or Controller. It does not know how it is displayed. It maintains an observer list and notifies registered views whenever its state changes.
2. The View: Renders the Model state to the screen and handles visual presentation. It registers itself as an Observer on the Model. When notified, it queries the Model to refresh its presentation.
3. The Controller: Interprets user input gestures (button clicks, keyboard input, HTTP requests) and translates them into appropriate business method calls on the Model (and view state changes). It acts as the Strategy for the View.

The 3 Compounded Patterns in MVC

How GoF Patterns Combine
COMPOUND ARCHITECTURE Where Each GoF Pattern Lives in MVC
1. Observer Pattern

Model & View: The Model is the Subject; Views are Observers. Multiple views (e.g. pie chart, table, progress bar) register with the same model and update in sync without model coupling.

2. Strategy Pattern

View & Controller: The Controller is the Strategy for the View. The View delegates input interpretation to the controller strategy, allowing controllers to be swapped dynamically (e.g. edit mode vs read-only).

3. Composite Pattern

View GUI Hierarchy: The GUI itself is structured as a Composite of nested widgets (Window contains Panels, Panels contain Buttons, TextFields, Labels) rendered recursively.

Core Exam Practice & Model Solutions

Direct Question → Answer Format
Question 1: What is the Role of the Model in MVC? 3 Points

What is the role of the Model in the Model-View-Controller (MVC) architectural pattern?

Model Answer:
  1. State & Domain Logic: The Model encapsulates all core business data, application state, and business validation rules.
  2. Zero UI Dependency: The Model is completely independent of visual representation and input handling. It has no references to or knowledge of View or Controller classes.
  3. Publisher / Subject Role: The Model implements the Subject in the Observer pattern. When its state mutates, it notifies all registered View observers so they can synchronize their display.
Question 2: Which 3 GoF Patterns Compose the MVC Architecture? 6 Points

Name the three Gang of Four design patterns that form the classic MVC compound pattern and identify between which components each pattern operates!

Model Answer:
  1. Observer Pattern (between Model and View): The Model acts as Subject; Views act as Observers. Enables multiple independent views to stay in sync with domain state automatically.
  2. Strategy Pattern (between View and Controller): The Controller acts as the input handling Strategy for the View. Swapping controllers alters how user gestures manipulate the model.
  3. Composite Pattern (within the View): GUI components are organized as hierarchical part-whole trees (nested windows, panels, labels, buttons) treated uniformly.

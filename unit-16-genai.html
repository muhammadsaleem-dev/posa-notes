PILLAR 01 · FOUNDATIONAL INTENT

The Paradigm Shift: From Syntax Typist to System Auditor

The Rise of Commodity Code Generation

In 2026, Large Language Models (LLMs) can generate syntactically valid code in seconds. However, LLMs are fundamentally stochastic token predictors: they optimize for local plausibility, not global architectural integrity.

Without explicit structural direction, AI assistants generate tightly coupled procedural code, hardcode magic values, and introduce subtle dependency cycles ($ADP$ violations).

Patterns as High-Density Semantic Prompts

Design patterns provide the highest compression ratio in software engineering:

  • Telling an AI: "Implement a WeatherStation using Fowler's Quantity pattern, Observer for display feeds, and Strategy for forecast algorithms" immediately constrains the search space to clean, decoupled classes.
  • Patterns transform prompt engineering from vague wishful thinking into rigorous architectural specifications.

PILLAR 03 · AGENTIC ARCHITECTURES

Modern Agentic Patterns: Re-Imagining POSA for Autonomous AI

1. Router & Dynamic Dispatch (Strategy)

In multi-model architectures, a lightweight Router LLM inspects user intent and dynamically chooses which specialized model or agent to invoke (analogous to the GoF Strategy and Chain of Responsibility patterns).

2. Shared Multi-Agent Memory (POSA Blackboard)

Autonomous agents (Researcher, Coder, Reviewer) do not talk point-to-point. They read and update a shared, structured state store—an exact 2026 reincarnation of the POSA Blackboard Pattern!

3. Tool Calling Pipelines (Pipes & Filters)

Complex agent tasks stream through deterministic tool validation pipelines (Input Filter $\to$ Rate Limiter $\to$ LLM Execution $\to$ Output Sanitizer), identical to POSA Pipes & Filters.

4. Safety Guardrails (Decorator / Proxy)

Output validation layers wrap LLM generation calls to redact sensitive data, intercept prompt injections, and enforce JSON schemas, behaving as classical Proxy and Decorator wrappers.

PILLAR 07 · WEATHER STATION CODE

Weather Station Implementation: Compounding Quantity, Observer & GenAI

WeatherStationMasterclass.java · Multi-Pattern Synthesis 
package de.frankfurt.uas.posa.genai;

import java.util.*;

// 1. QUANTITY PATTERN: Type-safe unit representation
public record Quantity(double amount, String unit) {
    public Quantity toFahrenheit() {
        if ("C".equals(unit)) return new Quantity(amount * 1.8 + 32, "F");
        return this;
    }
}

// 2. OBSERVER PATTERN: Decoupled sensor telemetry broadcast
public interface WeatherObserver {
    void onMeasurement(Quantity temperature, Quantity pressure);
}

public class WeatherStation {
    private final List<WeatherObserver> observers = new ArrayList<>();

    public void register(WeatherObserver obs) { observers.add(obs); }
    public void broadcast(Quantity temp, Quantity press) {
        for (WeatherObserver o : observers) o.onMeasurement(temp, press);
    }
}

// 3. GENAI ADVISORY OBSERVER: Submits telemetry to LLM for forecast summary
public class AiForecaster implements WeatherObserver {
    @Override
    public void onMeasurement(Quantity temp, Quantity press) {
        String prompt = String.format(
            "Generate a natural weather advisory for Temp: %s, Pressure: %s",
            temp, press
        );
        System.out.println("AI Advisory: " + LlmClient.predict(prompt));
    }
}
PILLAR 08 · EXAM TRAPS & DEFENSE

Frankfurt UAS Examination Pitfalls (Prof. Dr. Jörg Schäfer)

Exam Trap 1: "Will AI eliminate software architects?"

Schäfer's Trap: "Since LLMs can write full applications from a prompt, software architecture is no longer needed."
Correct UAS Defense: False! AI eliminates syntax typing, but radically elevates the need for software architects. The architect must formulate system boundaries, define pattern guardrails, prevent cyclic package dependencies ($ADP$), and audit stochastic outputs for security and design smells.

Exam Trap 2: Weather Station Compound Architecture

Schäfer's Trap: "Which patterns collaborate in the Weather Station case study?"
Correct UAS Defense: Quantity Pattern (type-safe measurements preventing unit conversion errors) + Observer Pattern (broadcasting real-time telemetry to multiple decoupled displays and services) + Model-View-Controller (separating physical sensor hardware from presentation).

STAGE 02 OF 05 · CASE STUDY

The IoT Weather Station Case Study

Prof. Dr. Jörg Schäfer uses the Weather Station case study to illustrate how patterns seamlessly compound:

1. Martin Fowler Quantity Pattern

Physical sensors record temperatures in Celsius and Fahrenheit, wind speeds in knots and km/h, and pressures in hPa and inHg. Using raw double values leads to dimensional disaster (like NASA's Mars Climate Orbiter). The Quantity Pattern ensures mathematical operations are dimensionally sound.

2. GoF Observer & MVC

The physical weather station acts as the Subject. An arbitrary number of decoupled displays (mobile app, LED wall display, statistical logger, and AI weather advisory service) act as Observers. New displays can be added at runtime without modifying the sensor code.

Frankfurt UAS Examination Drills (Prof. Dr. Jörg Schäfer)

Exam Drill 1 · Role of the Engineer How does the rise of Generative AI coding assistants transform the role of the software architect?

Official Model Answer:

The engineer transforms from a mechanical syntax typist into an architectural evaluator, specifier, and auditor.

Because AI can generate thousands of lines of syntax instantly, the architect's primary responsibility is establishing structural guardrails, decomposing systems into bounded modules, enforcing package coupling metrics ($ADP, SDP, SAP$), and auditing stochastic AI code against architectural drift and design smells.

Exam Drill 2 · Weather Station Synthesis Describe how the Quantity pattern and Observer pattern resolve distinct forces in the IoT Weather Station case study.

Official Model Answer:

  • Quantity Pattern: Resolves the force of dimensional type safety and unit conversion incompatibility (preventing arithmetic errors between Celsius and Fahrenheit or metric and imperial pressure).
  • Observer Pattern: Resolves the force of open-ended display extensibility, allowing new physical LED screens, web dashboards, or AI forecasters to subscribe to sensor broadcasts dynamically without modifying sensor hardware drivers.
Exam Drill 3 · Semantic Prompting Why does prompt engineering that uses formal pattern names produce higher-quality code than natural language task descriptions?

Official Model Answer:

Design pattern names represent semantic compression. During pre-training on millions of open-source repositories, LLMs form dense latent representations of patterns like Strategy, Observer, or Composite. Citing a formal pattern activates these modular, decoupled topological priors, preventing the LLM from defaulting to naive monolithic procedural code.
